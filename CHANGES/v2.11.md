## Version 2.11 (under development)

This page contains changes that will end up in 2.11

Most inputs written for PLUMED 2.10 run with PLUMED 2.11 without changes. The [migration guide](https://www.plumed.org/doc-master/developer-doc/html/_migration211.html)
lists the inputs that stop with an error or give different results, and what to write instead.

### Highlights

  - Exact restart with the new [CHECKPOINT](CHECKPOINT.md) directive: PLUMED writes its own checkpoint file, and a run restarted from it reproduces the uninterrupted run bitwise.
  - `pip install plumed` installs the python interface together with a PLUMED kernel and the `plumed` command, on Linux, macOS and Windows.
  - PLUMED can be built natively on Windows with Microsoft Visual C++, using CMake.
  - PLUMED ships the thread-MPI library of GROMACS: a PLUMED built without MPI can run its command line tools on several threads (`--tmpi-threads N`),
    and, with the GROMACS 2026 patch, can be used with a GROMACS built with thread-MPI and run on several thread-MPI ranks.
  - MPI is chosen when PLUMED runs, not when it is built: one PLUMED built without MPI can use the MPI library of the MD code that loads it
    (the GROMACS 2026 patch passes it), or an MPI provider library built afterwards for MPICH or Open MPI (`plumed mkmpi`, or the conda `plumed-mpi` packages).
  - Faster calculations: the positions and forces are shared with the MD code faster; [OPES_METAD](OPES_METAD.md) uses its exact neighbor list by default;
    [FIT_TO_TEMPLATE](FIT_TO_TEMPLATE.md) and [RESET_CELL](RESET_CELL.md) are 2 to 5 times faster; the forces on the eigenvectors of [DIAGONALIZE](DIAGONALIZE.md) scale as N^2 instead of N^4;
    [sum_hills](sum_hills.md) is several times faster; the Debye sums of [SAXS](SAXS.md) and [SANS](SANS.md) can be computed on the GPU with a plugin (`USEGPU`).
  - [MOLINFO](MOLINFO.md) (and every action that reads a reference structure) reads mmCIF files, with chain ids of any length, insertion codes and alternate locations.
  - Just-in-time compilation of [CUSTOM](CUSTOM.md) expressions and custom switching functions on AArch64 (including Apple Silicon), enabled by default.
  - [METAD](METAD.md) and [PBMETAD](PBMETAD.md) share the same grids, kernels and hills files, and grids are extended automatically; [sum_hills](sum_hills.md) has been revised;
    [METAINFERENCE](METAINFERENCE.md) and the ISDB collective variables with `DOSCORE` share one implementation of Metainference.
  - New modules: tensor-train metadynamics ([TTMETAD](TTMETAD.md)), kinetic ensemble refinement against NMR data ([KENREF](KENREF.md)), the xSPRINT coordinates ([XSPRINT](XSPRINT.md)),
    the order parameters of liquid crystals ([NEMATIC_ORDER](NEMATIC_ORDER.md)), permutationally invariant features for neural-network CVs ([PINES](PINES.md)) and functions for frozen path biases;
    new reactive Voronoi collective variables ([VORONOI_COORDINATION](VORONOI_COORDINATION.md)).
  - Data files written field by field can be written in HDF5 format; [driver](driver.md) reads dcd and pdb trajectories with its own readers and, with chemfiles, many more formats (the molfile plugins of VMD were removed).
  - Many inputs that crashed, hung or gave `nan` now stop with an error that names the action and the keyword to change.
    Keywords of older versions of PLUMED that were renamed are read again as their replacement, with a warning in the log.

### Changes that can change your results

The entries below give the details; the main cases are:

  - The default kernel of [KDE](KDE.md), [HISTOGRAM](HISTOGRAM.md), [RDF](RDF.md) and [PAIRENTROPY](PAIRENTROPY.md) is a Gaussian stretched to go to zero at its cutoff, as in [METAD](METAD.md).
  - The kernels of [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) are force-shifted at `KERNEL_CUTOFF`.
  - [METAD](METAD.md) and [PBMETAD](PBMETAD.md): no Gaussian is added at the first step of a new simulation, PBMETAD uses stretched Gaussians, and `ADAPTIVE=DIFF` restarts its statistics from the hills file.
  - [UPPER_WALLS](UPPER_WALLS.md) and [LOWER_WALLS](LOWER_WALLS.md) acting on a periodic argument do not apply the periodic boundary conditions to the difference between the argument and `AT`.
  - [JCOUPLING](JCOUPLING.md) with `TYPE=CUSTOM` needs `A`, `B` and `C`, and `SHIFT` is zero by default. `ARG=*` leaves out the values that the action cannot use.
  - Functions of vectors are evaluated also where all their arguments are zero (e.g. [CUSTOM](CUSTOM.md) with `FUNC=x+1`); [MOMENTS](MOMENTS.md) of periodic variables were wrong.
  - [COORD_ANGLES](COORD_ANGLES.md) with more than one central atom; [GYRATION](GYRATION.md) with `TYPE=RGYR_1` and `TYPE=RGYR_3` (they were swapped).
  - Wrong forces were fixed in [CENTER](CENTER.md) and [COM](COM.md) with `PHASES` in non-orthorhombic cells, [MATRIX_PRODUCT](MATRIX_PRODUCT.md) of sparse matrices,
    [TORSIONS_MATRIX](TORSIONS_MATRIX.md), [SASA_LCPO](SASA_LCPO.md), [CALIBER](CALIBER.md) with `SCALE`, [EMMI](EMMI.md) with `REWEIGHT`, [MOVINGRESTRAINT](MOVINGRESTRAINT.md) with `VERSE`
    and [simplemd](simplemd.md) with `sigma` different from 1; a wrong virial in [PIV](PIV.md) with `COM` and in functions of the bond vectors that are not rotationally invariant
    (e.g. [FCCUBIC](FCCUBIC.md), [TETRAHEDRAL](TETRAHEDRAL.md) and [SIMPLECUBIC](SIMPLECUBIC.md)); [NEIGHBORS](NEIGHBORS.md) with `NHIGHEST` larger than one; wrong values in
    [EEFSOLV](EEFSOLV.md) with `TEMP_CORRECTION` and [CS2BACKBONE](CS2BACKBONE.md) with several chains.
  - All random numbers come from a new generator (see "Core, performance and input"): the same `SEED` gives a different stream of random numbers than in previous versions.

### Features that have been removed

  - The molfile plugins of VMD: the `--mf_` options of [driver](driver.md) are aliases of the PLUMED readers, and amber crd, trj and g96 trajectories can no longer be read
    (see "Structures, trajectories and data files"). The configure options `--enable-molfile-plugins` and `--enable-external-molfile-plugins` were removed.
  - The ArrayFire implementation of [SAXS](SAXS.md) and [SANS](SANS.md) (`GPU` flag and `DEVICEID` keyword): use `USEGPU` with the openaccPTM plugin,
    which uses the GPU of the MD code.
  - The `SVD` flag of [RDC](RDC.md) (and its `exp`, `Sxx`, `Syy` and `Szz` components), which needed GSL and computed no forces. PLUMED does not use GSL anymore (`--enable-gsl` was removed).
  - The `CUTOFF` keyword of [RDF](RDF.md) and [PAIRENTROPY](PAIRENTROPY.md): the error message gives the replacement.
  - The patches for GROMACS 2022.5 and 2023.5: the patches available are those for GROMACS 2024.3, 2025.0 and 2026.0.
  - The `--enable-boost_graph` configure option (see the developer section).

### Changes relevant for users:

#### New modules and actions

  - [TTMETAD](TTMETAD.md) (module `ttsketch`): metadynamics in which the bias is periodically compressed into a tensor train, which keeps memory and cost bounded with many collective variables.
    `WALKERS_MPI` works also with more than one MPI rank per walker.
  - [KENREF](KENREF.md) (module `kenref`, which needs the external KEnRef library): kinetic ensemble refinement of an ensemble of replicas against NMR relaxation observables.
  - [XSPRINT](XSPRINT.md) (module `xsprint`): the extended SPRINT coordinates, computed from several shells around each atom.
  - [NEMATIC_ORDER](NEMATIC_ORDER.md) and [FERRONEMATIC_ORDER](FERRONEMATIC_ORDER.md) (module `liquid_crystal`, on by default): order parameters of the isotropic, nematic and ferronematic phases.
  - [PINES](PINES.md) (module `pines`): permutationally invariant atomic-level features for collective variables based on neural networks.
  - [PATH_LOGMEANEXP](PATH_LOGMEANEXP.md), [PROBABILITY_MIX](PROBABILITY_MIX.md) and [CONDITIONAL_PATH](CONDITIONAL_PATH.md) (module `pathbias`): functions for frozen complete-path biases over synchronized replicas.
  - [VORONOI_COORDINATION](VORONOI_COORDINATION.md), [VORONOI_DISTANCE](VORONOI_DISTANCE.md) and [VORONOI_POSITION](VORONOI_POSITION.md): a smooth Voronoi assignment of atoms to centers,
    to follow defects whose identity changes in reactive processes such as proton transfer.
  - [OPES_METAD](OPES_METAD.md) with `WALKERS_MPI` has a `WALKERS_SHARED_BIAS` flag: the beads of one ring polymer deposit with the bead-averaged bias as common weight.
  - [GYRATION](GYRATION.md) accepts numbered `ATOMS1`, `ATOMS2`, ... and then computes a vector with one value per group of atoms.
  - [ACCUMULATE](ACCUMULATE.md), [DUMPVECTOR](DUMPVECTOR.md), [DUMPGRID](DUMPGRID.md) and [DUMPCUBE](DUMPCUBE.md) have a `DO_AFTER_FINAL_STEP` flag, and [COLLECT](COLLECT.md) an `ANALYZED_AT_END` flag,
    to accumulate, write or analyse the data at the end of the trajectory also when its length is not a multiple of `STRIDE`.
  - [READ](READ.md) has an `IGNORE_COMPONENT` flag, to read a component (e.g. `d.x`) as a plain value.
  - The experimental openaccPTM plugin (`plugins/openaccPTM`, compiled separately with the NVIDIA HPC SDK) adds the `USEGPU` flag to some actions,
    e.g. [DISTANCE](DISTANCE.md), [KDE](KDE.md), [SAXS](SAXS.md) and [SANS](SANS.md), computed on the GPU with OpenACC.

#### Restart and checkpoints

  - New [CHECKPOINT](CHECKPOINT.md) directive for an exact restart: PLUMED writes its own checkpoint file (one per replica, atomic write, previous one kept as `_prev`)
    when the MD engine writes its checkpoint (`doCheckPoint` signal, as in the GROMACS patches) or every `STRIDE` steps. The checkpoint stores the state of the actions at the start
    of the checkpointing step and the sizes of all the output files: at restart the files are truncated to those sizes (the lines written after the checkpoint by the interrupted run are
    removed, see [#37](https://github.com/plumed/plumed2/issues/37)) and the checkpointing step is computed again, which reproduces the uninterrupted run bitwise. The field header is not
    printed again at restart. Actions store their state with `writeCheckpoint`/`readCheckpoint`; those that have a state but do not store it yet are listed in a warning
    ([MOVINGRESTRAINT](MOVINGRESTRAINT.md) is the first ported action). `plumed checkpoint --dump` prints a checkpoint file;
    [driver](driver.md) has `--checkpoint-stride` (sends the signal like an MD engine) and `--restart-from-checkpoint` (presents the checkpointing step again, like GROMACS `-cpi`).
    When the MD engine never sends the signal, a checkpoint of the state after the last step (i.e. for the next step) is also written at the end of the run,
    as `plumed_final.cpt` for `plumed.cpt`, when the engine calls `runFinalJobs` ([driver](driver.md), [simplemd](simplemd.md) and [pesmd](pesmd.md) do) or, otherwise,
    when PLUMED is finalized (if the last step was completed and not because of an error);
    `RESTART_FROM=AUTO` reads it when it exists, unless the engine gives a different restart step (`setRestartStep`, now also sent by [driver](driver.md) with `--restart-from-checkpoint`).
    [METAD](METAD.md) and [PBMETAD](PBMETAD.md) store their full state (grid or hills, hill schedule, adaptive-hill statistics, work, acceleration, c(t),
    hills read from the other walkers): with CHECKPOINT the hills files are trimmed and not read at restart, and the first-hill rule is not needed.
    [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) store their full state (kernels, normalization, weights, adaptive sigma, neighbor list):
    with CHECKPOINT the KERNELS file is trimmed and neither it nor STATE_RFILE is read at restart.
    [METAINFERENCE](METAINFERENCE.md) and the ISDB collective variables with `DOSCORE` store the Monte Carlo state (sigma, scale, offset, ftilde, the three random number generators,
    acceptance counters, weights, sigma-mean histories), [EDS](EDS.md) its couplings, running statistics and random generator, [DRR](DRR.md) the fictitious particles, the ABF and CZAR grids and the thermostat
    (the umbrella integration estimator is not stored): with CHECKPOINT the status, restart and `.drrstate` files are not read at restart.
    [ABMD](ABMD.md) stores the running minimum and the white-noise generators, [EXTENDED_LAGRANGIAN](EXTENDED_LAGRANGIAN.md) the fictitious positions and velocities and the Langevin generator, and [ACCUMULATE](ACCUMULATE.md) and [COLLECT](COLLECT.md) the accumulated or collected data (grids, vectors and matrices, with their shape), so that averages, histograms and time series continue exactly.
    [COMMITTOR](COMMITTOR.md) stores the basin, [MAXENT](MAXENT.md) the Lagrangian multipliers, their averages and works (the LAGMULT file is not read), [READ](READ.md) the position in the file, [RANDOM_EXCHANGES](RANDOM_EXCHANGES.md) the state of the generator of the exchanges, and [EFFECTIVE_ENERGY_DRIFT](EFFECTIVE_ENERGY_DRIFT.md) the drift and the data of the previous step (with more processes the data of all of them is gathered in the checkpoint and redistributed at restart, also to a different number of processes; the restart is then exact up to the rounding of the sum over the processes).
    [LOGMFD](LOGMFD.md) stores the fictitious variables, velocities, forces, thermostat variables and works (and cuts its plain `logmfd.out` and `replica.out` files at the checkpoint size), [FISST](FISST.md) the weights, partition estimates and averaged forces, [RESCALE](RESCALE.md) the bias, Monte Carlo state and selector, [EMMI](EMMI.md) sigma, the Monte Carlo state, the regression scale and the average weights, and [EMMIVOX](EMMIVOX.md) scale, offset and Bfactors with their Monte Carlo state. The neighbor lists of [EMMI](EMMI.md) and [EMMIVOX](EMMIVOX.md) are rebuilt at the first step. The per-step files of the model overlap/density of [EMMI](EMMI.md) and [EMMIVOX](EMMIVOX.md) are no longer appended to when they exist (they are renamed as a backup).
    [VES](VES_LINEAR_EXPANSION.md) biases and optimizers, [ADAPTIVE_PATH](ADAPTIVE_PATH.md), the maze actions and [TTMETAD](TTMETAD.md) keep an internal state that is not stored yet: they are listed in the warning.
    An action with `RESTART=NO` is not restored from the checkpoint and starts from scratch; a global `RESTART NO` together with CHECKPOINT is an error.
  - At a restart from a step S given by the MD engine, PLUMED removes from the files it appends to the lines written at or after S, so that they continue exactly where the restarted simulation starts,
    as GROMACS does with its own files ([#37](https://github.com/plumed/plumed2/issues/37)); the hills of [METAD](METAD.md) and [PBMETAD](PBMETAD.md), the kernels of [OPES_METAD](OPES_METAD.md),
    the DELTAFS of [OPES_EXPANDED](OPES_EXPANDED.md), the LAGMULT of [MAXENT](MAXENT.md) and the alpha file of [VES_DELTA_F](VES_DELTA_F.md) are trimmed before being read. Only the last lines with a time
    not earlier than that of S are removed (earlier runs whose time restarted from zero are kept), and they are moved to a file `bck.trimmed.N.name`; the field header is not printed again when the trimmed file ends with the same one; files without a time field are not trimmed, compressed (`.gz`) files are. The trimming is on by default and is switched off with
    `RESTART NO_TRIM`, or for the files of one action with the `NO_TRIM` flag (see [RESTART](RESTART.md)). The GROMACS patches (2024.3, 2025.0, 2026.0) pass S after `-cpi` (also with `-noappend`), and
    [driver](driver.md) does it with `--restart --initial-step S`. New command `setRestartStep` for MD engines (API version 12).
  - The documentation of [ABMD](ABMD.md), [MOVINGRESTRAINT](MOVINGRESTRAINT.md) and [EXTENDED_LAGRANGIAN](EXTENDED_LAGRANGIAN.md) says what is restored by [RESTART](RESTART.md) without [CHECKPOINT](CHECKPOINT.md).

#### Biases

  - The opes module ([OPES_METAD](OPES_METAD.md), [OPES_EXPANDED](OPES_EXPANDED.md), ...) is now compiled by default, also in the python wheels;
    `--enable-modules=-opes` disables it.
  - New `LINEAR` flag for [ABMD](ABMD.md): the ratchet is applied to the distance from the target, V=K/2(d-d_m)^2, instead of the squared distance, V=K/2(d^2-d_m^2)^2. In this way the stiffness does not depend on the distance from the target and K has the units of an energy divided by the square of the CV. With `LINEAR`, `MIN`, `NOISE` and the `_min` components are distances. The checkpoint of [ABMD](ABMD.md) records the flag and a restart with a different setting is an error.
  - The kernels of [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) are now force-shifted at KERNEL_CUTOFF, so that both their value and their derivative go to zero at the cutoff.
    Previously they were energy-shifted: their value went to zero at the cutoff, but their derivative jumped to zero there (see [#1463](https://github.com/plumed/plumed2/pull/1463)).
    Bias values and kernel heights change only in the far tails of the kernels, and forces change slightly, mostly early in a simulation.
    The script `FES_from_State.py` of the OPES tutorial uses the new kernels.
  - [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) now use their neighbor list by default, since it is exact and never slower; it can be switched off with NLIST_OFF.
    The NLIST flag is still accepted, and only adds the `nlker` and `nlsteps` components as in previous versions.
    The NLIST_PACE_RESET flag has no effect (it is accepted with a warning): with WALKERS_MPI, the neighbor list is now always reset after each deposition.
  - [METAD](METAD.md) and [PBMETAD](PBMETAD.md) have been revised; PBMETAD now uses the grids, kernels and hills files of METAD. Results change in the following cases:
    - Grids are extended automatically when a Gaussian does not fit in them (GRID_MIN and GRID_MAX give the initial range; GRID_SIZE_LIMIT sets the maximum number of points); GRID_SPACING can be given without GRID_MIN and GRID_MAX. A grid read with GRID_RFILE(S) can have any range on the lattice of the grid in input.
    - No Gaussian is added at the first step of a simulation; when continuing a simulation, a Gaussian is added at the first step unless the hills file already contains it (also when restarting from a grid, see [#267](https://github.com/plumed/plumed2/issues/267)). PBMETAD never added a Gaussian at the first step of a run.
    - ADAPTIVE=DIFF: when restarting, the statistics of the fluctuations are initialized from the last hills of the hills file (DIFF_FROM_SCRATCH restores the old behavior); with replica exchange the running average is restarted when an exchange is accepted, instead of stopping with an error ([#26](https://github.com/plumed/plumed2/issues/26)); PRECAL_DIFF accumulates the statistics also outside the update window ([#1328](https://github.com/plumed/plumed2/issues/1328)).
    - An incomplete last line of the hills file (an interrupted run) is removed when restarting ([#727](https://github.com/plumed/plumed2/issues/727)).
    - PBMETAD uses stretched Gaussians, as METAD and as written in its hills files (biases change by about 0.2%); it requires the temperature (TEMP); partitioned families with ADAPTIVE and families in a different order than the arguments are fixed.
    - INTERVAL with a grid: beyond the limits the force is zero also within the grid cell that contains a limit; with NLIST the neighbor list is built at the limit.
    - Multiple walkers: the hills files are read by the first MPI process of each walker and broadcast (with several processes per walker the run could hang); restarting from the grid of a walker (WALKERS_N) adds only the hills of the other walkers that are not in the grid (their number is written in a comment after the grid); the hills and grid files are read without the replica suffix, as they are written.
    - Grids are filled with OpenMP and are faster also without OpenMP; the c(t) reweighting factor (CALC_RCT) is fixed with GRID_SPARSE; ACCELERATION and FREQUENCY_ADAPTIVE are restarted correctly.
    - PBMETAD: BIASFACTOR=1 means, as in METAD, that no bias is applied and the hills files and grids contain the estimate of -F (TAU can be given instead of HEIGHT); new PRECAL_DIFF and STORE_GRIDS keywords, as in METAD.
    - Inputs that crashed or gave meaningless results are now errors (e.g. WALKERS_RSTRIDE=0, negative SIGMA, HEIGHT or TAU, ADAPTIVE on a grid without SIGMA_MIN also in PBMETAD and when reading a grid in METAD, a SELECTOR that is not defined in PBMETAD).
  - [sum_hills](sum_hills.md) has been revised:
    - variables whose name contains `sigma_`, `time`, `min_` or `max_` are found correctly (they made it crash, [#1226](https://github.com/plumed/plumed2/issues/1226)); `--spacing` can be used without `--min` and `--max`; `--negbias` is correct also when the run was not well tempered; with MPI the derivatives were zero.
    - `--sort time` (or `clock`) merges the hills files of multiple walkers in order of time, so that the free energies written with `--stride` follow the simulation ([#1351](https://github.com/plumed/plumed2/issues/1351)).
    - `--average` computes the time average of the bias, and `--basins` writes the free-energy differences between basins at each output, to check convergence.
    - The hills are summed several times faster (the Gaussians are computed as products over the variables), and with MPI the grids are summed once per output.
    - The documentation has been rewritten. It now states that `--histo` does not reweight the points, and shows how to compute a free energy from a biased simulation with [driver](driver.md), [REWEIGHT_BIAS](REWEIGHT_BIAS.md) and [HISTOGRAM](HISTOGRAM.md).
  - The examples in the documentation of [HISTOGRAM](HISTOGRAM.md), [REWEIGHT_BIAS](REWEIGHT_BIAS.md), [REWEIGHT_METAD](REWEIGHT_METAD.md) and [METAD](METAD.md) that use `LOGWEIGHTS` now set `NORMALIZATION`, without which HISTOGRAM stops with an error.
  - [UPPER_WALLS](UPPER_WALLS.md) and [LOWER_WALLS](LOWER_WALLS.md) acting on periodic arguments do not apply periodic boundary conditions to the difference between the argument and AT anymore
    ([#658](https://github.com/plumed/plumed2/issues/658)). Previously each wall acted on half of the periodic domain, so that e.g. an upper and a lower wall at $\pm 2$ on a torsion
    pushed it out of the interval $[-2,2]$ when its value was beyond $\pm(\pi-2)$. AT must now be within the periodic domain of the argument.
    Results are unchanged when the argument stays further than half a period from AT.
  - Fixes and speed-ups in the biases (src/bias):
    - A bias that does not set the force on an argument at a step now applies no force to it. Before, the force of the last step in which it was set was applied again:
      [MOVINGRESTRAINT](MOVINGRESTRAINT.md) with `VERSE=U` or `VERSE=L` pushed the argument while it was on the side where the restraint does not act (with zero bias, and with a wrong work);
      [ABMD](ABMD.md) pushed the argument while it was moving closer to the target than ever before; [VES_LINEAR_EXPANSION](VES_LINEAR_EXPANSION.md) pushed the argument when it was outside the range of the basis functions.
    - [RESTRAINT](RESTRAINT.md): with scalar arguments, `SLOPE` was ignored when its first value was written as `0.0` (e.g. `SLOPE=0.0,2.0`). With vector arguments, `KAPPA=0` for the first argument and a non-zero value for another one gave an input error,
      and `force2` was $k^2x^2+m^2$ instead of $(kx+m)^2$.
    - [UPPER_WALLS](UPPER_WALLS.md) and [LOWER_WALLS](LOWER_WALLS.md) acting on vectors gave `nan` with a non-integer `EXP`. They are also faster: with 20000 distances, an upper and a lower wall cost 2.3 instead of 8.5 milliseconds per step.
      [RESTRAINT](RESTRAINT.md) on a non-periodic vector uses one action less per argument (with 20000 distances, `KAPPA` and `SLOPE`: 2.6 instead of 4.1 milliseconds per step).
    - [MAXENT](MAXENT.md): with `ERROR_TYPE=LAPLACE` the Lagrangian multipliers were never kept within the range allowed by the prior; the average between `TSTART` and `TEND` was too large by one term
      when an update happened exactly at `TEND`; the `_error` components were always zero; an unknown `TYPE` or `ERROR_TYPE` is now an error (it gave no bias).
    - Biases stop with an error when an argument is a vector with more than one element (only its first element was used, e.g. by [BIASVALUE](BIASVALUE.md)).
    - Input errors instead of crashes or meaningless results: [MOVINGRESTRAINT](MOVINGRESTRAINT.md) without `STEP0`, `KAPPA0` or `AT0`, or with a `VERSE` other than U, L, B;
      [EXTENDED_LAGRANGIAN](EXTENDED_LAGRANGIAN.md) with non-positive `KAPPA` or `TAU` or negative `FRICTION`; [REWEIGHT_TEMP_PRESS](REWEIGHT_TEMP_PRESS.md) with `REWEIGHT_TEMP=0`.
  - [MAXENT](MAXENT.md): a [RESTART](RESTART.md) without [CHECKPOINT](CHECKPOINT.md) rebuilt the average of the Lagrangian multipliers between `TSTART` and `TEND` with the multipliers shifted by one update and not converted for `TYPE=INEQUAL`;
    the restart is now exact when the MD code repeats the step it restarts from (it is still not exact in general: use [CHECKPOINT](CHECKPOINT.md)). The `work` components are now in energy units (they lacked the factor $k_BT$).
  - [OPES_METAD](OPES_METAD.md) with `WALKERS_MPI` and `EXCLUDED_REGION`: when only some walkers were in the excluded region, the simulation hung or mixed up the kernels of the walkers.
    A walker in the excluded region now does not deposit, while the others do.
  - Wrong inputs that crashed or gave `nan` in the OPES module now stop with a message: [ECV_UMBRELLAS_LINE](ECV_UMBRELLAS_LINE.md) with `SIGMA` or `SPACING` not greater than zero,
    [OPES_EXPANDED](OPES_EXPANDED.md) with `PRINT_STRIDE=0` or a `STATE_RFILE` without DeltaF values, temperatures not greater than zero in [ECV_MULTITHERMAL](ECV_MULTITHERMAL.md) and [ECV_MULTITHERMAL_MULTIBARIC](ECV_MULTITHERMAL_MULTIBARIC.md),
    and [ECV_UMBRELLAS_FILE](ECV_UMBRELLAS_FILE.md) with no umbrellas or sigmas not greater than zero. `TEMP=0` is an error in all the actions that read `TEMP`.

#### Collective variables, molecules and virtual atoms

  - When using [MOLINFO](MOLINFO.md) with the `WHOLE` flag, PBCs in the following actions will be reconstructed using a minimum spanning tree based on the coordinates stored in the MOLINFO reference PDB.
    Fixed the tree construction and parent/child indexing in this reconstruction: previously actions such as [CENTER](CENTER.md), [RMSD](RMSD.md), and [GYRATION](GYRATION.md) could silently use split coordinates (see [#1496](https://github.com/plumed/plumed2/issues/1496)).
  - When the reference pdb of [MOLINFO](MOLINFO.md) with the `WHOLE` flag has a CRYST1 record with space group P 1, PLUMED now checks along each chain that the reference is whole in that box, and writes a warning to the log naming the atoms that are across the periodic boundary from the atom before them. Before, a split reference made [WHOLEMOLECULES](WHOLEMOLECULES.md) split whole molecules without any warning.
  - Bug fixes in the secondary structure collective variables ([ALPHARMSD](ALPHARMSD.md), [ANTIBETARMSD](ANTIBETARMSD.md), [PARABETARMSD](PARABETARMSD.md), [SECONDARY_STRUCTURE_RMSD](SECONDARY_STRUCTURE_RMSD.md) and [SECONDARY_STRUCTURE_DRMSD](SECONDARY_STRUCTURE_DRMSD.md)):
    - the two strands of a sheet were made whole together as a single chain, so the value of [ANTIBETARMSD](ANTIBETARMSD.md) and [PARABETARMSD](PARABETARMSD.md) changed when a strand was wrapped by the periodic boundary conditions (it is again as in 2.9); with `NOPBC` the periodic boundary conditions are now not used at all, also for the `STRANDS_CUTOFF` distance;
    - the default `R_0` of the three shortcuts is 0.08 nm in whatever length unit is set with [UNITS](UNITS.md) (it was 0.08 in the units of the input, i.e. 10 times smaller than intended with `UNITS LENGTH=A`, which gave almost no helix, beta etc.);
    - segments that do not contain 30 atoms (e.g. three atoms) read and wrote out of bounds and crashed; segments from 2 to 30 atoms are now supported and wrong input (different sizes of the segments, indices outside ATOMS, wrong size of `STRUCTURE`, missing `STRUCTURE`, `ALIGN_STRANDS` without 30 atoms, empty `RESIDUES`) is an error;
    - [SECONDARY_STRUCTURE_DRMSD](SECONDARY_STRUCTURE_DRMSD.md) read out of bounds when scaling the derivatives, returned nan forces when a segment had distance zero from its reference, and did not give an error when all the distances in the reference were shorter than `BONDLENGTH`; the examples in its documentation had no `BONDLENGTH` and did not use Angstrom as the `STRUCTURE` unit;
    - [ANTIBETARMSD](ANTIBETARMSD.md) and [PARABETARMSD](PARABETARMSD.md) with `STYLE=inter` crashed when a chain contained a single residue; they are now an error only when no pair of strands can be built.
  - Fixes in the collective variables:
    - [DIHEDRAL_CORRELATION](DIHEDRAL_CORRELATION.md) with `ATOMS` (a single variable) crashed: the atoms were never requested.
    - [CHARGE](CHARGE.md) returned the masses of the atoms instead of their charges, and an error is given when the MD code does not provide the charges.
    - [RMSD](RMSD.md) with `DISPLACEMENT` and `TYPE=OPTIMAL` (or `TYPE=OPTIMAL-FAST`) on a reference with more than one frame: the forces on the distances (`.dist`) were zero.
    - [PATHMSD](PATHMSD.md) with `NEIGH_STRIDE=0` crashed with a floating point exception, and `LAMBDA=0` gave `nan`; they are now errors, as is using only one of `NEIGH_SIZE` and `NEIGH_STRIDE`.
    - [CONTACTMAP](CONTACTMAP.md) with a single contact and `CMDIST` failed saying that `REFERENCE` was missing even if it was given; `REFERENCE` is now applied to all the contacts. No contacts is an error.
    - [GHBFIX](GHBFIX.md): the pairs of types in the `PARAMS` file that are not in the `TYPES` table were assigned to the first type, so that they could overwrite the parameters of that type depending on their order in the file.
      They are now skipped (their number is written in the log). The parameters (`D_0`, `D_MAX`, `C`), the types and the atom indexes are checked, and unknown keywords are not silently ignored.
    - [EEFSOLV](EEFSOLV.md) with `TEMP_CORRECTION` had no effect because of a wrong condition. The heat capacity term was also in the wrong units (cal/mol/K used as kcal/mol/K) and had the wrong sign with respect to Lazaridis and Karplus:
      the correction is now zero at 298.15 K and, as expected, makes the solvation free energy less favourable at higher temperature. **Results with `TEMP_CORRECTION` change** (they were identical to those without the flag).
    - [ERMSD](ERMSD.md) ignored `NOPBC` (the molecule was always made whole) and did not check the residue indexes in `PAIRS`.
    - [PCARMSD](PCARMSD.md) reads out of bounds if the eigenvectors and the average structure have a different number of atoms; it is now an error. [DRMSD](DRMSD.md) is an error, instead of undefined behavior, if no pair is within the cutoffs.
    - [DIMER](DIMER.md) checks that `DSIGMA` is consistent with the number of replicas before using it; [GYRATION](GYRATION.md) without atoms is an error; the [RMSD](RMSD.md) shortcut closes the reference file after counting its frames.
    - [GYRATION](GYRATION.md) with `TYPE=RGYR_1` and `TYPE=RGYR_3` gave the smallest and the largest principal radius of gyration, the opposite of the documentation,
      when computed with `WEIGHTS` other than the masses or ones (e.g. the examples in the manual) or with `PHASES` (since 2.10). Without them the values were already correct.
    - Variables that use `MultiColvarTemplate` with single precision no longer require charges when they do not use them.
    - [GHBFIX](GHBFIX.md) is about 7% faster (the cutoff is tested before looking up the types of the atoms), with identical results; [COORDINATION](COORDINATION.md) and the variables that share its implementation do not allocate the per-thread buffers of the derivatives when running on a single thread.
  - Fixes in the virtual atoms (src/vatom):
    - [CENTER](CENTER.md) and [COM](COM.md) with `PHASES` (also `SAFE_PHASES`, when it uses the fast implementation) applied wrong forces to the atoms in non-orthorhombic cells, because the derivatives were transposed.
      Cubic and orthorhombic cells were not affected. The reference forces of the regtest `rt71c`, which has two triclinic frames, were wrong and have been updated; a new regtest (`rt-center-triclinic`) checks the forces, validated against numerical derivatives, and the masses and charges of the centers.
    - [CENTER](CENTER.md) and [COM](COM.md) read the masses and charges once when they are constant (as they are when they come from the MD engine) instead of recomputing them, and the mass-based weights, at every step. The mass and charge of a [CENTER](CENTER.md) with `WEIGHTS` are now also updated if they change.
      A missing mass is reported with a single warning instead of one line per atom, and the center now stops with an error with `SET_MASS<=0`, with weights that sum to zero, with a total mass equal to zero, or with `PHASES` when the weighted sines and cosines cancel out exactly (all of these gave `nan` or were silently ignored).
    - [GHOST](GHOST.md) stops with an error, instead of giving `nan`, when the first two atoms coincide or the three atoms are collinear.
    - [FIXEDATOM](FIXEDATOM.md) with `SCALED_COMPONENTS` prints a warning when the cell is not set (the atom was silently put in the origin).
    - [ARGS2VATOM](ARGS2VATOM.md): the checks on the arguments now reject vectors and empty lists (they were skipped because of a wrong logical operator).
  - Fixes in the multicolvar shortcuts (src/multicolvar):
    - [COORD_ANGLES](COORD_ANGLES.md) (and [ANGLES](ANGLES.md) with `SWITCH`) with more than one central atom also included the angles between bonds that start from different atoms. **Results change in that case**:
      the angles are now calculated separately for each central atom and summed, as in the formula in the documentation. The central atom is no longer one of its own neighbours (the result was `nan` if it was in `GROUP`).
    - The numbered `MORE_THAN1`, `MORE_THAN2`, ... of the shortcuts that use weights ([COORD_ANGLES](COORD_ANGLES.md) and [CLUSTER_PROPERTIES](CLUSTER_PROPERTIES.md)) used the `LESS_THAN` actions: they failed or, if `LESS_THAN1` was also given, returned the number of values below the threshold.
    - [INPLANEDISTANCES](INPLANEDISTANCES.md) crashed with more atoms in `VECTOREND` than in `VECTORSTART`, and gave wrong distances with more than one atom in `VECTORSTART`. Empty `VECTORSTART`, `VECTOREND` and `GROUP` are errors.
    - `MIN`, `MAX`, `ALT_MIN` and `HISTOGRAM` of the old multicolvar syntax check their options: `MIN={FOO=3}` was read as `BETA=3` and `NBINS=0` gave no output. [ANGLES](ANGLES.md) and [ALPHABETA](ALPHABETA.md) say what is missing when atoms or reference values are not given.
    - [PLANES](PLANES.md) no longer lists the keywords of the old multicolvar syntax (`MEAN`, `LESS_THAN`, ...) and [UWALLS](UWALLS.md) no longer lists `CATOMS`, `GROUP` and `SWITCH`: they were never read and gave an error.
  - [DISTANCE_FROM_SPHERICAL_CONTOUR](DISTANCE_FROM_SPHERICAL_CONTOUR.md) counted the atoms close to the line from `ORIGIN` to `ATOM` twice, and without `ARG` this overflowed a buffer (crash or memory corruption).
    The radius changes slightly (in the regtest, in the third decimal).
  - [COORD_ANGLES](COORD_ANGLES.md) gave `nan` when two bonds were parallel or antiparallel (the dot product of the unit vectors was out of $[-1,1]$ by rounding).
  - The `cudaCoord` plugin (`CUDACOORDINATION` and `CUDACOORDINATIONFLOAT`) computes the minimum image with the full box: with a box rotated by [FIT_TO_TEMPLATE](FIT_TO_TEMPLATE.md) (e.g. in funnel setups) the results were wrong.
    It is also faster, in particular when GROMACS keeps its data on the GPU: only the needed atoms are moved to and from the GPU, the cell lists are rebuilt only when the atoms have moved, and the molecules are not made whole at every step. The error for a skewed box that is too small for `D_MAX` is now raised on all the MPI processes (it was raised only on the one that owns the GPU, and the others waited for it), and wrong `NN`, `MM` (not positive, or equal) and `R_0` give an error also when `D_MAX` is not given.
  - The `cudaCoord` plugin uses the GPU assigned to PLUMED by the MD code, otherwise the one the MD code is using (as the openaccPTM plugin), writes it in the log,
    and always gives the MD code back its own GPU.
  - [WRAPAROUND](WRAPAROUND.md) with at least 128 atoms in `AROUND` finds the closest reference atom with a cell search instead of a loop over all of them,
    with identical results, in orthorhombic and triclinic boxes. With 18000 atoms wrapped around 2000 atoms: 0.4 instead of 5.9 seconds for 30 steps (orthorhombic),
    0.2 instead of 11.6 seconds for 10 steps (rhombic dodecahedron).
  - [ERMSD](ERMSD.md) is much faster for large RNA molecules: the pairs of bases are found with linked cells and a list that is rebuilt automatically when the bases have moved
    (new keywords `PAIR_SEARCH` and `NL_BUFFER`), and the calculation is parallelized with MPI and OpenMP. The results are the same up to rounding.

#### Structures, trajectories and data files

  - Residue numbers in the pdb files read by [MOLINFO](MOLINFO.md) and by the `TEMPLATE` of [SAXS](SAXS.md), as well as in the [CS2BACKBONE](CS2BACKBONE.md) and [EMMIVOX](EMMIVOX.md) inputs, can be negative (e.g. tags in protein constructs, see [#1089](https://github.com/plumed/plumed2/issues/1089)).
    Negative residues can be selected with e.g. `@phi--3`, `@phi-A-3` or `@phi-A_-3` and in ranges such as `RESIDUES=-10--1` or `RESIDUES=-5-10`.
    Previously negative residue numbers were silently converted to very large positive numbers.
    `RESIDUES=all` (e.g. in [ALPHARMSD](ALPHARMSD.md)) and the `ONEBEAD` mapping of [SAXS](SAXS.md) now only use the residues present in the pdb file, so they also work when the numbering has gaps.
  - Fixed `RESIDUES=all` in [ALPHARMSD](ALPHARMSD.md), [ANTIBETARMSD](ANTIBETARMSD.md), [PARABETARMSD](PARABETARMSD.md) and [WHOLEMOLECULES](WHOLEMOLECULES.md) when the pdb file of [MOLINFO](MOLINFO.md) contains chains that use the same residue numbers (e.g. all chains starting from residue 1):
    the backbone atoms of all the chains were taken from the first chain. With an explicit list of residues (e.g. `RESIDUES=2-10`), residue numbers present in more than one chain are still taken from the first chain, and a warning is printed.
  - Structures in mmCIF (PDBx/mmCIF) format: files with extension `.cif` or `.mmcif` given to [MOLINFO](MOLINFO.md) (and to every action that reads a reference structure, e.g. [RMSD](RMSD.md)) are read as mmCIF,
    with the CIF parser of [gemmi](https://gemmi.readthedocs.io) 0.7.5, included in PLUMED (`src/gemmi`, or a gemmi installed in the system with `--enable-system-gemmi`).
    The atoms are read from the `_atom_site` table (first model only), with the author (`auth_`) chain ids, residue numbers, residue names and atom names, and the `label_` ones where those are missing,
    as written by the wwPDB, by the AlphaFold database and by GROMACS. The atoms are numbered with `_atom_site.id`.
    The file is streamed through the parser: a file with one million atoms is read in about 1.5 seconds and 280 MB, the memory of the structure itself.
    Malformed files (empty, not CIF, unterminated strings, a wrong number of values, a unit cell that cannot be read or that is not valid) stop with a message that gives the line.
  - Chain ids with more than one character (from mmCIF files) are selected with the underscore: `@phi-A1_12` is residue 12 of chain A1 (the chain is what precedes the last underscore).
  - Insertion codes (column 27 of PDB files, `pdbx_PDB_ins_code` of mmCIF files) are read: residues 52 and 52A are different residues, selected as `@phi-A_52` and `@phi-A_52A`.
    The dihedrals that involve the previous or the next residue (`@phi-`, `@psi-`, `@omega-`, `@alpha-`, `@epsilon-`, `@zeta-`) take the residue before or after in the file, so that 52, 52A, 52B, 53 are consecutive,
    and the backbone of `RESIDUES=all` in [ALPHARMSD](ALPHARMSD.md) and the other secondary structure variables includes all of them in order. Without insertion codes nothing changes.
  - Alternate locations (column 17 of PDB files, `label_alt_id` of mmCIF files): only the first location found in each residue is read, with the atoms that have no alternate location;
    the number of atoms skipped is written in the log of [MOLINFO](MOLINFO.md). Before, all the locations were read, so that a residue had two atoms with the same name.
    The element symbol (columns 77-78, `type_symbol`) is read.
  - GROMACS TPR files (extension `.tpr`) given to [MOLINFO](MOLINFO.md) (and to every action that reads a reference structure) are read with chemfiles,
    when PLUMED is configured with `--enable-libchemfiles` (chemfiles 0.10.4 or later). The structure is that of the PDB file written by `gmx editconf -f topol.tpr -o reference.pdb`:
    the atoms are numbered in the order of the file, the sequences of residues connected by bonds (the protein and nucleic acid chains) are the chains A, B, ...,
    and the other residues (water, ions...) have no chain and are numbered after them. [driver](driver.md) does not accept a TPR file with `--pdb`.
  - New keyword `ATOM_ID` of [MOLINFO](MOLINFO.md): with `ATOM_ID=order` the atoms of the structure (PDB or mmCIF) are numbered 1,2,3... in the order of the file,
    instead of using the serial numbers or the mmCIF ids (e.g. for the PDB files of the wwPDB, whose serial numbers count the TER records).
  - Residue names of four characters, written by GROMACS in the columns 18-21 of a PDB file, are read in full (they were cut to the columns 18-20).
    In [MOLINFO](MOLINFO.md) the four-character variants of the amino acids (`HISE`, `LYSH`, `ASPH`, `CYS2`, ...) are recognized as the amino acid of their first three characters, as before.
    The other actions that read residue names from a reference structure see the full name: e.g. [PIV](PIV.md) with `COM` needs `ATOMTYPES=wate` for the residue `water` written by GROMACS (it was `wat`).
  - The PDB reader skips the numbered REMARK records of the wwPDB (`REMARK 465 ...`): those that contain `=` stopped it with an assertion.
    [MOLINFO](MOLINFO.md) no longer stops with "found second start of chain" when a chain appears in more than one block of the file
    (e.g. the ligands and waters of a chain written after the other chains, as in the files of the wwPDB): the log lists each block.
    `@water` includes the residues named `HOH` (the waters of the wwPDB).
  - [MOLINFO](MOLINFO.md) selectors based on a python interpreter (`@mda:`, `@mdt:`, `@vmd:` and `@vmdexec:`) now terminate the interpreter, and the processes it starts (e.g. `vmd`),
    when PLUMED finishes. Previously only the shell used to launch the interpreter was signaled, so that the temporary file created by the selector script could be left behind
    and processes that did not exit when their input was closed could be left running.
  - A PDB file whose lines end after the coordinates (without occupancy and beta) is read with occupancy and beta equal to 1 (they were left undefined).
  - HDF5 tables: the files written field by field (PRINT, the hills of METAD, the kernels of OPES_METAD, ...) are written in HDF5 format
    when their name ends with `.h5`, with full precision (one dataset per field, constant fields as attributes, a new group when the fields
    change). PLUMED reads them wherever it reads text files, restarts work as with text files (appending, trimming, [CHECKPOINT](CHECKPOINT.md)),
    grids and state files (GRID_WFILE, DUMPGRID, STATE_WFILE) can be HDF5 tables too (restarts from them do not lose precision),
    and the new [h5convert](h5convert.md) tool converts them to text files and back ([#1560](https://github.com/plumed/plumed2/issues/1560),
    see [Files](Files.md)). `./configure` now uses libhdf5 when it finds it (also through pkg-config, e.g. on Debian/Ubuntu), and the conda package uses the hdf5 package of conda.
    The calls to HDF5 are serialized, so that HDF5 tables can be written by the threads of the embedded thread-MPI (e.g. replicas with `--multi`)
    also with an HDF5 library that is not thread safe.
  - The molfile plugins of VMD were removed; [driver](driver.md) and [benchmark](benchmark.md) read all their trajectory formats with readers of PLUMED:
    - New options `--idcd` (dcd files written by CHARMM, NAMD, X-PLOR and other codes: either endianness, 32 or 64 bit record markers, fixed atoms, unit cell)
      and `--ipdb` (pdb files with frames separated by END or ENDMDL records; as with `--mf_pdb`, only the coordinates and the CRYST1 record are read; also from standard input).
      They give the same coordinates and cells as `--mf_dcd` and `--mf_pdb` of v2.10, except that pdb coordinates are read in double precision.
    - `--mf_xtc`, `--mf_trr`, `--mf_gro`, `--mf_pdb` and `--mf_dcd` are still accepted for this release, with a warning: they are the same as `--ixtc`, `--itrr`, `--igro`, `--ipdb` and `--idcd`.
    - The amber crd format (`--mf_crd`, `--mf_crdbox`), trj and g96 can no longer be read (the driver stops with a message suggesting to convert the trajectory),
      and the configure options `--enable-molfile-plugins` and `--enable-external-molfile-plugins` (VMD plugins installed on the system) were removed.
    - The triclinic cells that CHARMM (c36 and later) writes in dcd files as the shape matrix are read correctly: the molfile plugin took them for lengths and angles,
      which gave an invalid box with which the driver never ended. A box that is not finite (e.g. a CRYST1 record with zero angles) is now an error.
    - An incomplete last frame of a dcd file ends the trajectory with a warning, as for xtc and trr files.
  - New configure option `--enable-libchemfiles` (off by default) to link the [chemfiles](https://chemfiles.org) library (0.10 or later; GROMACS TPR files need 0.10.4):
    [driver](driver.md) and [benchmark](benchmark.md) can then read any trajectory format of chemfiles with the new option `--itraj`
    (e.g. Amber NetCDF, LAMMPS, TNG, GROMACS TPR, and files compressed with gzip, xz or bzip2). The format is guessed from the extension of the file
    or given with `--traj-format`; the masses and charges of TPR and LAMMPS Data files are passed to PLUMED. `plumed config has libchemfiles` tells whether it is available.
  - Corrupted xtc and trr files read with the xdrfile implementation (`--ixtc` and `--itrr` of the driver and [benchmark](benchmark.md)) no longer crash PLUMED or corrupt the memory.
    The xtc decoder did not check for corrupted data (a frame with more atoms than the first one, compressed data larger than the frame, an index of the table of small integers out of range, a run beyond the last atom, a zero range of the coordinates),
    and a trr frame with more atoms than the first one overflowed the buffer as well; a negative number of atoms or a trr file with a wrong magic number is now rejected.
    A corrupted frame is now an error: the driver used to take any error of the xdrfile reader for the end of the trajectory and stopped without a message.
    An incomplete last frame (a file truncated by a simulation that stopped while writing it) ends the trajectory with a warning, as in GROMACS.
  - xtc files with magic number 2023, which GROMACS 2023 and later writes for frames with more than 298261617 atoms, can be read with `--ixtc`,
    and [DUMPATOMS](DUMPATOMS.md) writes this format for such frames. The xdrfile implementation reads and writes frames of up to 500 million atoms.
  - A DL_POLY_4 trajectory (`--idlp4`) read from standard input failed, since the header of the file was not read, and [benchmark](benchmark.md) read the header as a frame when it went back to the beginning of the file.

#### Functions, kernels, grids and matrices

  - In [KDE](KDE.md), [HISTOGRAM](HISTOGRAM.md), [RDF](RDF.md) and [PAIRENTROPY](PAIRENTROPY.md) you can now use the switching function 
    syntax detailed in [LESS_THAN](LESS_THAN.md) to set up the parameters for the kernel to use in kernel density estimation. 
    __The default kernel that is used in these actions has changed.__  In the new version of the code the kernel is a Gaussian 
    that has been stretched and scaled to ensure that it is zero for all values greater than the cutoff. In other words, the default
    behaviour in these methods is now the same as the behavior used for [sum_hills](sum_hills.md) and [METAD](METAD.md).
    The `CUTOFF` keyword of [RDF](RDF.md) and [PAIRENTROPY](PAIRENTROPY.md) has been removed: an input that uses it stops with a message that gives the replacement, `KERNEL={GAUSSIAN D_MAX=x}` with x=sqrt(2*CUTOFF).
  - The `CUTOFF` keyword of [DISTANCE_MATRIX](DISTANCE_MATRIX.md) is now `LINKCELL_CUTOFF`, to make its purpose clearer (`CUTOFF` is still read, with a warning).
  - [COMBINE](COMBINE.md) has a new CIRCULAR flag to combine periodic arguments as angles: the output is the argument of $\sum_i c_i e^{i p_i \theta_i}$
    (with the default coefficients, the circular mean of the arguments), scaled to the domain given with PERIODIC ([#164](https://github.com/plumed/plumed2/issues/164)).
  - Bug fixes in the functions. Results change in the following cases:
    - Elements of a vector whose arguments are all zero (e.g. the output of [LESS_THAN](LESS_THAN.md) with a D_MAX, or of a [CONTACT_MATRIX](CONTACT_MATRIX.md) row sum) were set to zero
      without evaluating the function, which is wrong when the function is not zero there: e.g. [CUSTOM](CUSTOM.md) with `FUNC=x+1`, [COMBINE](COMBINE.md) with PARAMETERS,
      [LESS_THAN](LESS_THAN.md) and [BETWEEN](BETWEEN.md) around zero. For example, [COORDINATIONNUMBER](COORDINATIONNUMBER.md) with LESS_THAN did not count the atoms with no neighbors
      within D_MAX.
    - [CUSTOM](CUSTOM.md) set the function to zero when an argument that is zero (with zero derivative) appeared in a product anywhere in the expression,
      e.g. `FUNC=x*cos(y)+1` or `FUNC=exp(x)*y`. Only the arguments that multiply the whole expression are now used for this.
    - Forces were lost when [SORT](SORT.md), [MOMENTS](MOMENTS.md), [HIGHEST](HIGHEST.md) or [LOWEST](LOWEST.md) take a single vector or matrix in input and only components other than
      the first are biased (e.g. `sort.4`, `m.moment-3`), and they were applied to the wrong elements of a sparse matrix.
    - [MOMENTS](MOMENTS.md) of periodic variables were wrong (the circular mean was shifted by half a period); the derivative of the circular mean is now included.
    - [PRODUCT](PRODUCT.md), and thus [DETERMINANT](DETERMINANT.md), gave nan for negative values (it was computed as the exponential of a sum of logarithms) and did not accept periodic scalars.
    - [FUNCPATHMSD](FUNCPATHMSD.md) and [FUNCPATHGENERAL](FUNCPATHGENERAL.md) no longer underflow far from the path (FUNCPATHMSD gave nan); FUNCPATHMSD accepts [DISTANCE](DISTANCE.md) arguments again;
      NEIGH_SIZE requires a positive NEIGH_STRIDE.
    - The documentation of [BESSEL](BESSEL.md) now states that it computes the exponentially scaled function $e^{-|x|}I_0(x)$.
  - Errors instead of segmentation faults for a kernel name that is not known in [KDE](KDE.md), [HISTOGRAM](HISTOGRAM.md) and the other actions that use kernels (e.g. `KERNEL=GAUSIAN`),
    and for a label that is not an action in `DISSIMILARITIES` of the LANDMARK_SELECT actions (e.g. [LANDMARK_SELECT_FPS](LANDMARK_SELECT_FPS.md)) and in `MATRIX` of [SPRINT](SPRINT.md).
  - [MFILTER_MORE](MFILTER_MORE.md) on a vector (e.g. the output of [LOCAL_Q6](LOCAL_Q6.md)) stopped with the error `map::at`.
  - [DUMPGRID](DUMPGRID.md) and [DUMPCUBE](DUMPCUBE.md) with the default `STRIDE=0` (output at the end of the run) of a grid that was never calculated,
    e.g. the instantaneous [RDF](RDF.md) of the default `CLEAR=1`, gave a segmentation fault at the end of the run. It is now an error that says to use `STRIDE`.
  - [EVALUATE_FUNCTION_FROM_GRID](EVALUATE_FUNCTION_FROM_GRID.md) with vector arguments stopped with "argument is a function on a grid, which is not accepted".
  - Grids defined with `GRID_SPACING` and without `GRID_BIN` (e.g. in [KDE](KDE.md), [HISTOGRAM](HISTOGRAM.md), [INTERPOLATE_GRID](INTERPOLATE_GRID.md) and [REFERENCE_GRID](REFERENCE_GRID.md))
    now follow the convention of [METAD](METAD.md): the grid ends at `GRID_MAX`, with `ceil((GRID_MAX-GRID_MIN)/GRID_SPACING)` bins and a spacing not larger than `GRID_SPACING`.
    They had one more point, past `GRID_MAX`, and a point just past the end of a grid was read outside it (e.g. with `KERNEL=DISCRETE` or [INTERPOLATE_GRID](INTERPOLATE_GRID.md));
    this is now the error "point is outside grid range", as for points further away.
  - Wrong grid inputs that crashed, ran out of memory or gave a grid of `nan` now stop with a message: `GRID_BIN=0`, `GRID_SPACING` not greater than zero or `GRID_MAX` not larger than `GRID_MIN`
    (e.g. in [KDE](KDE.md), [HISTOGRAM](HISTOGRAM.md), [SPHERICAL_KDE](SPHERICAL_KDE.md) and [REFERENCE_GRID](REFERENCE_GRID.md)), a negative `BANDWIDTH` in [KDE](KDE.md) and [HISTOGRAM](HISTOGRAM.md),
    [REFERENCE_GRID](REFERENCE_GRID.md) with neither `GRID_BIN` nor `GRID_SPACING`, [FIND_SPHERICAL_CONTOUR](FIND_SPHERICAL_CONTOUR.md) with `NPOINTS=0`,
    [DISTANCE_FROM_CONTOUR](DISTANCE_FROM_CONTOUR.md) without `POSITIONS`, and `DENSITY` not greater than zero in [RDF](RDF.md) and [PAIRENTROPY](PAIRENTROPY.md).
  - The forces on the eigenvectors computed by [DIAGONALIZE](DIAGONALIZE.md) (used e.g. when biasing [SPRINT](SPRINT.md)) are computed in a time that scales
    as N^2 instead of N^4 with the size N of the matrix. With a 200x200 contact matrix, applying the forces went from 5 seconds to 0.3 milliseconds per step.
  - Symmetric positive definite matrices (e.g. the covariance matrices of multivariate Gaussians) are inverted with a Cholesky factorization instead of being diagonalized,
    which is 5 to 25 times faster for matrices with up to 10 rows and about 4 times faster for large matrices; matrix products are 2 to 5 times faster.
    [METAD](METAD.md) with `ADAPTIVE=DIFF` and three CVs depositing a Gaussian at every step is about 20% faster, and reading 20000 multivariate Gaussians when restarting is about 25% faster.
  - When no derivatives are needed, [DIAGONALIZE](DIAGONALIZE.md) computes only the requested eigenvalues and eigenvectors (from the largest one down to the smallest requested one) instead of all of them.
    With `VECTORS=1` this is 3 to 4 times faster: e.g. for a 1000x1000 contact matrix it went from 180 to 70 milliseconds per frame. [CLASSICAL_MDS](CLASSICAL_MDS.md) also benefits: with 2000 frames the analysis is about 20% faster.
    The results are identical.
  - [MATRIX_PRODUCT](MATRIX_PRODUCT.md) gave wrong forces when its first matrix is sparse (e.g. a [CONTACT_MATRIX](CONTACT_MATRIX.md) with `D_MAX`).
    With more than one thread, and a sparse second matrix, some forces could also be lost; with `AVOID_THREAD_GATHER` the forces were wrong for any sparse matrix.
  - [TORSIONS_MATRIX](TORSIONS_MATRIX.md) gave wrong forces when the same molecules are in `POSITIONS1` and `POSITIONS2` and no `MASK` is used, with three molecules or more,
    and with `AVOID_THREAD_GATHER`.
  - The virial of the `x`, `y` and `z` components of adjacency matrices (e.g. [CONTACT_MATRIX](CONTACT_MATRIX.md) and [DISTANCE_MATRIX](DISTANCE_MATRIX.md) with `COMPONENTS`) was transposed.
    The pressure was thus wrong in constant-pressure simulations that bias a function of the bond vectors that is not rotationally invariant: [FCCUBIC](FCCUBIC.md), [TETRAHEDRAL](TETRAHEDRAL.md),
    [SIMPLECUBIC](SIMPLECUBIC.md), [COORDINATION_SHELL_FUNCTION](COORDINATION_SHELL_FUNCTION.md), [COORDINATION_SHELL_AVERAGE](COORDINATION_SHELL_AVERAGE.md) or a [CUSTOM](CUSTOM.md) function of the components.
    The forces on the atoms were right, and rotationally invariant functions such as [Q6](Q6.md) were not affected.
  - [NEIGHBORS](NEIGHBORS.md) with `NHIGHEST` larger than one selected no element (the number of neighbors was taken from `NLOWEST`).
    A row with fewer elements larger than zero than the neighbors requested (e.g. a matrix with negative elements) gives an error that explains this.
  - [MOMENTS](MOMENTS.md) of a list of vectors stopped at an assertion; the moments are now computed element by element.
  - [TRANSPOSE](TRANSPOSE.md) of a matrix of collected data with a single row (e.g. the example of [DISSIMILARITIES](DISSIMILARITIES.md) with one frame) crashed.
  - Wrong matrix inputs that hung, crashed or stopped at an assertion now stop with a message: a zero cutoff for the link cells (e.g. `LINKCELL_CUTOFF=0` in [DISTANCE_MATRIX](DISTANCE_MATRIX.md), `R_0=0`),
    [LOCAL_AVERAGE](LOCAL_AVERAGE.md) and [LOCAL_CRYSTALINITY](LOCAL_CRYSTALINITY.md) without `SPECIES`, [ENVIRONMENTSIMILARITY](ENVIRONMENTSIMILARITY.md) with `CRYSTAL_STRUCTURE=CUSTOM` without `REFERENCE`,
    and [GSYMFUNC_THREEBODY](GSYMFUNC_THREEBODY.md) without `FUNCTION1`. A function of matrices with different sparsity patterns (e.g. [CUSTOM](CUSTOM.md) of a [CONTACT_MATRIX](CONTACT_MATRIX.md) and an [OUTER_PRODUCT](OUTER_PRODUCT.md))
    stopped at an assertion: the error now says to use `MASK`, and the examples of [CLUSTER_WITHSURFACE](CLUSTER_WITHSURFACE.md), [FIND_SPHERICAL_CONTOUR](FIND_SPHERICAL_CONTOUR.md) and [HEXACTIC_PARAMETER](HEXACTIC_PARAMETER.md) now do so.
  - A function of a sparse matrix (e.g. [CUSTOM](CUSTOM.md) with `FUNC=1-x` on a [CONTACT_MATRIX](CONTACT_MATRIX.md) with `D_MAX`) is only evaluated on the elements that the matrix stores:
    when the function is not zero for zero arguments the elements that are not stored were silently wrong (zero). This is now an error that says to use `MASK`
    (the diagonal of a matrix built from a single group, which is never stored, is not taken into account).
  - Functions of sparse matrices are faster, since the elements of the matrices are looked up only when needed.
  - Adjacency matrices (e.g. [CONTACT_MATRIX](CONTACT_MATRIX.md)) accept `CUSTOM` switching functions that return negative values.
  - [KDE](KDE.md) of the elements of a [CONTACT_MAP](CONTACT_MAP.md), and [HISTOGRAM](HISTOGRAM.md) of values read with [READ](READ.md) by [driver](driver.md) with `--noatoms` (segmentation fault), are fixed.

#### ISDB, SAXS and SASA

  - [SAXS](SAXS.md) and [SANS](SANS.md) give an error when an atom is listed more than once in `ATOMS` (the two copies, at distance zero, made the intensities `nan`).
  - [METAINFERENCE](METAINFERENCE.md) and the ISDB collective variables with `DOSCORE` ([NOE](NOE.md), [PRE](PRE.md), [RDC](RDC.md), [JCOUPLING](JCOUPLING.md), [CS2BACKBONE](CS2BACKBONE.md), [SAXS](SAXS.md)) now share one implementation of Metainference. Results change in the following cases:
    - New SEED keyword to make the Monte Carlo sampling of the uncertainties, scale, offset and ftilde reproducible (by default the seed is still taken from the clock).
    - SELECTOR and NSELECT were ignored by the collective variables with `DOSCORE` (the history of sigma mean and the averaged weights were always those of the first selector value); they now work as in METAINFERENCE.
    - With `DOSCORE` and RESTART, a missing status file was created empty and then read as a restart (averaged weights starting from zero); it is now a new start, as in METAINFERENCE.
    - NOISETYPE=GENERIC could not be restarted (ftilde was not read back from the status file).
    - OPTSIGMAMEAN with a single replica gave NaN after AVERAGING steps: the standard error of the mean is not defined with one replica, and sigma mean now keeps its initial value.
    - Monte Carlo moves larger than the allowed interval (DSIGMA, DSCALE or DOFFSET larger than the range of the flat prior) could leave the interval; with NOISETYPE=GENERIC and OPTSIGMAMEAN, sigma could move above SIGMA_MAX when sigma mean exceeded it (it is now kept equal to sigma mean, with a warning).
    - More than one DSIGMA with NOISETYPE=GAUSS or OUTLIERS is an error, as for SIGMA0, SIGMA_MIN and SIGMA_MAX.
    - Moves of chunks of sigmas (MC_CHUNKSIZE) and of ftilde are computed from energy differences, and the history of sigma mean (OPTSIGMAMEAN with AVERAGING) no longer grows in cost with AVERAGING. NOE, PRE, RDC and JCOUPLING no longer look up their components by name at every step (with 3000 NOEs and `DOSCORE` a step went from 24 to 1.7 ms).
  - [METAINFERENCE](METAINFERENCE.md) includes stability fixes when restarting while parameter optimisation is running.
  - Bug fixes and performance improvements in the other ISDB actions. Results change in the following cases:
    - [CALIBER](CALIBER.md): with SCALE different from 1 or with REGRES_ZERO the forces were not the derivatives of the bias (they were divided instead of multiplied by the scale). The data file is checked (it was read with a duplicated last line), its first time is no longer assumed to be zero, and a simulation time outside the data is an error.
    - [CS2BACKBONE](CS2BACKBONE.md): the non-bonded term excluded the residues adjacent in sequence without looking at the chain, so with chains numbered from 1 the contacts between residues with close numbers in different chains were dropped. ATOMS and TEMPLATE must now contain the same atoms (they were silently assumed to be numbered from 1 in the same order). With MPI less data are communicated.
    - [EMMI](EMMI.md): with REWEIGHT the forces and the derivative with respect to the bias were wrong when the weights of the replicas were different; atoms with the same tabulated overlap could be dropped from the neighbor list. New SEED keyword. With MPI the derivatives of the overlaps are no longer summed at every step; OpenMP parallelization; the scale regression is done once instead of on every rank and replica.
    - [EMMIVOX](EMMIVOX.md): new SEED keyword; the neighbor sphere uses a cell list (it was O(voxels x atoms)); results no longer depend on the number of OpenMP threads; the score is summed in double precision.
    - [SAXS](SAXS.md) and [SANS](SANS.md): faster Debye sums (sine and cosine for all the q values by angle addition), with `DOSCORE` only the contracted derivatives are summed over the MPI ranks, faster SASA for ONEBEAD. Without `DOSCORE` the derivatives of the intensities (with respect to all the atoms with ONEBEAD) are stored with OpenMP threads, and the forces on the components of the ISDB collective variables are applied with OpenMP threads. With SIGMARES the self term of the intensity is now smeared too. The random deuteration of SANS is drawn by the first rank with PLUMED's own generator.
    - [JCOUPLING](JCOUPLING.md) with `DOSCORE` now sets the j-# components (they were always zero); [RDC](RDC.md) with `DOSCORE` no longer allocates derivatives for each coupling.
    - [RESCALE](RESCALE.md) uses PLUMED's random number generator and has a SEED keyword; [SELECT](SELECT.md) and RESCALE stop if the SELECTOR does not exist; [SHADOW](SHADOW.md) checks that exactly one replica uses REFERENCE; [BAIES](BAIES.md) checks that the atoms in DATA_FILE are in ATOMS.
    - [RDC](RDC.md): the `SVD` flag was removed (see "Features that have been removed").
  - [JCOUPLING](JCOUPLING.md) with `TYPE=CUSTOM` used uninitialised Karplus parameters when A, B or C were not given; A, B and C are now compulsory with `TYPE=CUSTOM`, and SHIFT is zero by default.
  - [SAXS](SAXS.md) now accepts the `MARTINI_FF` keyword to select the Martini form-factor generation: `MARTINI_FF=2` (default) keeps the existing Martini 2.2 protein and nucleic-acid form factors, while `MARTINI_FF=3` selects Martini 3 protein form factors.
  - [SAXS](SAXS.md) includes bug fixes related to the `ONEBEAD` approach and nucleic acid in some corner case, as well as general improvements in performances and SANS calculation. 
  - [SAXS](SAXS.md) includes new ions parameters that can be used both in `ATOMISTIC` and `ONEBEAD` modes.
  - [SAXS](SAXS.md) and [SANS](SANS.md): the ArrayFire implementation (`GPU` flag) has been removed. The Debye sum can now be computed on the GPU with the `USEGPU` flag, using a backend provided by a plugin (plugins/openaccPTM, OpenACC). With MPI each rank computes a share of the sum on its own GPU. On an A100 the sum is 20-40 times faster than on 32 CPU cores (see the README of the plugin).
  - [SAXS](SAXS.md) and [SANS](SANS.md) with `ONEBEAD`: the LCPO solvent accessible surface used for the solvation correction and the deuteration is several times faster, with the same results. Its neighbour list is kept between the updates and rebuilt only when the atoms have moved, and with MPI the atoms are split over the ranks.
  - [SAXS](SAXS.md) and [SANS](SANS.md) with `ONEBEAD`: the centres of mass of the beads and the derivatives with respect to the atoms are computed with OpenMP threads, and the virial is computed from the beads. With `USEGPU` and `DOSCORE` the derivatives of the intensities are no longer allocated on the CPU. This reduces the CPU time per step of the GPU runs.
  - [SASA_LCPO](SASA_LCPO.md) and [SASA_HASEL](SASA_HASEL.md) with `TYPE=TRANSFER` and without `DELTAGFILE` (free energies of transfer computed from the temperature)
    read the temperature at every step with a function that used memory already released: a crash or a wrong temperature, depending on the input.
    After the first step the free energies of transfer were also read from vectors that had been emptied (the values happened to be still in memory: a debug build stopped there).
  - [SASA_LCPO](SASA_LCPO.md): the derivatives (forces) included the terms of the atoms whose area is negative, which the value leaves out (in packed structures, a few percent of the elements of the derivatives were wrong). The value is unchanged.

#### Core, performance and input

  - The random number generator used by all the actions and tools (e.g. [simplemd](simplemd.md), [pesmd](pesmd.md), [METAINFERENCE](METAINFERENCE.md), [EMMI](EMMI.md), [EMMIVOX](EMMIVOX.md),
    [EXTENDED_LAGRANGIAN](EXTENDED_LAGRANGIAN.md), [ABMD](ABMD.md), [EDS](EDS.md), [RANDOM_EXCHANGES](RANDOM_EXCHANGES.md), the VES and DRR modules) is now xoshiro256**, a 64-bit generator
    with period 2^256-1 and uniform numbers with 53-bit resolution. The previous generator (ran1 from Numerical Recipes) had a period of about 2^31, which a Langevin thermostat
    on a thousand atoms exhausts in less than a million steps. The same `SEED` gives a different stream of random numbers.
    [TTMETAD](TTMETAD.md), the maze optimizers and [plumed benchmark](benchmark.md) also use it instead of the generators of the C++ standard library,
    whose numbers depend on the compiler.
  - Molecules are made whole (by [WHOLEMOLECULES](WHOLEMOLECULES.md) and by the actions that do it themselves, e.g. [CENTER](CENTER.md), [GYRATION](GYRATION.md), [SAXS](SAXS.md)) in a faster way, partly with OpenMP threads: the image of each atom is found from the original positions and the shifts are summed as integers. The images are the same as before; the atoms that are not moved keep their coordinates exactly, the others differ by rounding, and nothing is done without a box.
  - Positions and forces are shared with the MD code faster. The lists of the atoms needed by the actions are rebuilt only when they change,
    also when an MD code with domain decomposition passes the same local atoms at every step; the choice between copying all the atoms
    and copying only those that are needed (`PLUMED_FORCE_UNIQUE=auto`) is based on all the atoms needed by the active actions instead
    of on the largest single action; OpenMP threads are only used for large copies.
    With `plumed benchmark`, 7000 atoms and three [COORDINATION](COORDINATION.md) between one atom and 2207 atoms, "Sharing data" went
    from 82 to 7 microseconds per step in serial and from 84 to 25 microseconds with domain decomposition on two ranks.
  - Actions with a neighbor list (e.g. [COORDINATION](COORDINATION.md) with `NLIST`) request the reduced list of atoms only once after
    each update of the list, instead of at every step: requesting the same atoms made PLUMED rebuild the lists of atoms at every step.
  - [FIT_TO_TEMPLATE](FIT_TO_TEMPLATE.md) and [RESET_CELL](RESET_CELL.md), which move all the atoms, are 2 to 5 times faster: they loop
    directly on the arrays of positions and forces. With `plumed benchmark`, 7000 atoms and `TYPE=OPTIMAL` with 200 aligned atoms,
    FIT_TO_TEMPLATE went from 148 to 90 microseconds per step for the positions and from 260 to 48 for the forces. The results are identical.
  - PLUMED stops with an error, instead of crashing, when it has to apply forces on the atoms or on a value passed with [PUT](PUT.md)
    and the MD code did not pass the array for these forces. The size of the arrays passed with domain decomposition is now checked
    also when PLUMED is compiled without debug flags.
  - Updated the embedded Lepton and AsmJit libraries from OpenMM 8.6.1, preserving PLUMED-specific expression functions and semantics. Just-in-time compilation of [CUSTOM](CUSTOM.md) expressions and custom switching functions now supports AArch64, including Apple Silicon, and is enabled by default on supported architectures. It can be disabled with `./configure --disable-asmjit` or at runtime with `PLUMED_USE_ASMJIT=no`.
  - Fixes and speed-ups in the tools used by many actions:
    - Neighbor lists of [COORDINATION](COORDINATION.md) and similar variables with a single group of more than 32768 atoms (`GROUPA` only, with `NLIST`) contained wrong pairs and could crash (32-bit overflow).
    - With `NLISTCELLS` and `NOPBC`, the cells were built on the periodic box and close pairs on the two sides of the planes at half box were missed. `NLISTCELLS` now also keeps only the pairs within `NL_CUTOFF`, as `NLIST` does (the list contained all the pairs of neighboring cells, about 6 times more), and it is parallelized with MPI and OpenMP (with 20000 atoms and a list updated every 5 steps, 4.7 times faster in serial).
    - Neighbor lists built with several OpenMP threads have the pairs in the same order as in serial: before, the order depended on the timing of the threads, so that two runs with the same input could give slightly different results.
    - Link cells (used by `NLISTCELLS`, [CONTACT_MATRIX](CONTACT_MATRIX.md) and the other adjacency matrices) are built on every process without MPI communication, and their number is limited.
    - Shuffling (used by [METAINFERENCE](METAINFERENCE.md) with `MC_CHUNKSIZE` to choose the uncertainties that are moved) only produced cyclic permutations, so that the choice was not uniform (e.g. with two uncertainties, one step and chunks of one, the first uncertainty was never moved).
    - Text files (e.g. hills files, grids, colvar files) are read in chunks instead of one character at a time, and numbers are converted with `std::from_chars` (when available) instead of a string stream: [sum_hills](sum_hills.md) on 300000 hills went from 9.8 to 2.5 seconds.
    - `nan`, `inf` and `-inf`, as written by PLUMED in its output files, are read correctly; negative numbers are not accepted anymore where an unsigned integer is expected (e.g. `STRIDE=-1` was read as 4294967295).
    - Output files are written without two MPI collective operations per line, and with MPI they are opened only by the first process (the other processes open `/dev/null`): opening and truncating the same file from all the processes is slow on parallel file systems.
    - In single precision (e.g. the OpenACC implementation of [DISTANCE](DISTANCE.md)), periodic boundary conditions in triclinic boxes were applied with an error up to 4e-6 times the box size; they are now exact.
    - Values outside a grid on its lower side give an error on all architectures (on arm64, e.g. Apple Silicon, they gave the value of the first bin).
    - A `CUSTOM` switching function with a constant derivative (e.g. `SWITCH={CUSTOM FUNC=1-x R_0=1}`) stopped with "getVariableReference: Unknown variable".
  - Fixes and speed-ups in the core of PLUMED:
    - Less overhead per action and per step: OpenMP threads are used to clear the derivatives and to sum the forces of an action only when there is enough work.
      Before, two OpenMP regions were opened for every action at every step, which was expensive when PLUMED runs with several threads
      (e.g. GROMACS passes its number of OpenMP threads to PLUMED). With `plumed benchmark`, 400 atoms, 200 [DISTANCE](DISTANCE.md) and 200 [RESTRAINT](RESTRAINT.md),
      a step went from 226 to 85 microseconds with one thread and from 513 to 85 microseconds with two threads.
    - Forces on virtual atoms ([CENTER](CENTER.md), [COM](COM.md), ...) are applied 3 times faster: they were computed twice.
    - Reading an input with many actions is much faster (the time grew quadratically with the number of actions): 8000 [DISTANCE](DISTANCE.md) lines are read in 0.4 seconds instead of 17.5.
    - Forces on the elements of a sparse matrix that is not square (e.g. [CONTACT_MATRIX](CONTACT_MATRIX.md) with GROUPA, GROUPB and a cutoff) passed through [FLATTEN](FLATTEN.md)
      were added to the wrong elements, and a linear function of a flattened sparse matrix (e.g. its [SUM](SUM.md)) stopped with an error.
    - `UPDATE_IF ARG=... END` without a matching opening [UPDATE_IF](UPDATE_IF.md) is now an input error (it led to undefined behavior).
    - With replica exchange through the GREX interface (e.g. Hamiltonian replica exchange with GROMACS), PLUMED stops with an error if the two replicas exchange states of different size, instead of reading a truncated state.
    - The labels of the detailed timers (`DEBUG DETAILED_TIMERS`) were shifted after the actions that are computed during the update step.
    - The type of the arguments (scalar, vector, matrix, function on a grid) is checked against the types accepted by the action: the check always passed, so that e.g. a vector given to [RESTRAINT_SCALAR](RESTRAINT.md) or [MOVINGRESTRAINT](MOVINGRESTRAINT.md) was silently biased through its first element only. The error message lists the accepted types.
    - The set up of shortcuts that create an action with many numbered keywords is not quadratic anymore, e.g. [DISTANCES](DISTANCES.md) with `GROUPA` and `GROUPB` with 300k pairs of atoms takes 1.4 s instead of 94 s (`ActionShortcut::addToSavedInputLines`).
  - Fixes and speed-ups in the generic actions:
    - [PDB2CONSTANT](PDB2CONSTANT.md) and [READMASSCHARGE](READMASSCHARGE.md) kept only 6 significant digits of the values they read (reference positions and arguments, masses and charges).
      This affected the actions that read their reference through [PDB2CONSTANT](PDB2CONSTANT.md) ([RMSD](RMSD.md), [PATH](PATH.md), [GPATH](GPATH.md), [ADAPTIVE_PATH](ADAPTIVE_PATH.md), [PCAVARS](PCAVARS.md), ...):
      with a large `LAMBDA`, [PATH](PATH.md) and [PATHMSD](PATHMSD.md) on the same reference differed by 1e-4; they now agree.
    - [DUMPATOMS](DUMPATOMS.md) in xtc or trr format: with MPI, all the processes wrote the file; with [RESTART](RESTART.md) the frames were appended several times and the file was corrupted.
    - [DUMPPROJECTIONS](DUMPPROJECTIONS.md) ignored [RESTART](RESTART.md) and [FLUSH](FLUSH.md), was written by all MPI processes, and multiple replicas wrote the same file.
    - [EFFECTIVE_ENERGY_DRIFT](EFFECTIVE_ENERGY_DRIFT.md) was wrong with MD codes that reorder their atoms in serial runs (e.g. LAMMPS); with domain decomposition (e.g. GROMACS)
      the positions and forces of all the atoms were gathered on all the processes at every step, now only when the atoms move to another process.
    - [FIT_TO_TEMPLATE](FIT_TO_TEMPLATE.md) with an unknown `TYPE` did not align anything; it is now an error.
      With `TYPE=OPTIMAL` and a reference whose beta column is all zero (the beta column only weights the RMSD that FIT_TO_TEMPLATE returns, not the alignment), this RMSD was `nan`; it is now zero, and the alignment is unchanged.
    - [FISST](FISST.md) crashed (division by zero) at the first step when `OUT_OBSERVABLE` was not used; `PERIOD=0` is now an error.
    - [WRAPAROUND](WRAPAROUND.md) is faster (about 30% with an orthorhombic box), with identical results.
    - Errors instead of crashes or undefined behavior for [COMMITTOR](COMMITTOR.md) without basins, [CREATE_MASK](CREATE_MASK.md) with `TYPE=stride NZEROS=0`, [DUMPPDB](DUMPPDB.md) without `ARG` and `ATOMS`;
      [DUMPPDB](DUMPPDB.md) with `ATOMS` does not replace the names given with `ARG_NAMES` anymore. [UNITS](UNITS.md) prints the Boltzmann constant in the new units.
  - Wrong inputs that crashed PLUMED, found by running the examples of the manual and variants of them (`.ci/audit-inputs.py`), are now errors:
    - [BRIDGE_MATRIX](BRIDGE_MATRIX.md) ignored `GROUP` and stopped saying that no atoms had been specified;
    - [MAZE_OPTIMIZER_BIAS](MAZE_OPTIMIZER_BIAS.md) and the maze optimizers crashed when `OPTIMIZER` or `LOSS` named an action that does not exist;
    - [HISTOGRAM](HISTOGRAM.md) and [KDE](KDE.md) without `BANDWIDTH` (and a kernel other than `DISCRETE`) or without arguments, [COVARIANCE_MATRIX](COVARIANCE_MATRIX.md) without `ARG`,
      [OUTER_PRODUCT](OUTER_PRODUCT.md) and the functions without arguments (e.g. [CLUSTER_DIAMETER](CLUSTER_DIAMETER.md) without `ARG`), [LOCAL_CRYSTALINITY](LOCAL_CRYSTALINITY.md) without `GVECTOR1` and [XSPRINT](XSPRINT.md) with `NSHELLS=0`;
    - [SPHERICAL_HARMONIC](SPHERICAL_HARMONIC.md) and [CYLINDRICAL_HARMONIC](CYLINDRICAL_HARMONIC.md) with fewer arguments than vector components;
    - [SELECT_COMPONENTS](SELECT_COMPONENTS.md) with an element out of range (with a matrix, a column out of range silently selected an element of another row);
    - [WRAPAROUND](WRAPAROUND.md) with `GROUPBY=0` and [ACCUMULATE](ACCUMULATE.md) with `STRIDE=0` and `CLEAR` (division by zero).
  - A missing input file (e.g. with [INCLUDE](INCLUDE.md), [EXTERNAL](EXTERNAL.md), [PLUMED](PLUMED.md) or [PIV](PIV.md)) is an error instead of a failed assertion,
    and [PLUMED](PLUMED.md) with a `CHDIR` that does not exist is an error instead of an uncaught exception.
  - Keywords of older versions of PLUMED that were replaced by another keyword are read again as their replacement, with a warning in the log:
    `GRID` of [DUMPGRID](DUMPGRID.md) and [CONVERT_TO_FES](CONVERT_TO_FES.md), `MATRIX` of [DFSCLUSTERING](DFSCLUSTERING.md) and of the other actions that take a matrix,
    `DATA` of [HISTOGRAM](HISTOGRAM.md), `ATOMS` of [RDF](RDF.md), `SIGMA` of [PAIRENTROPY](PAIRENTROPY.md) and `CUTOFF` of [DISTANCE_MATRIX](DISTANCE_MATRIX.md) (now `LINKCELL_CUTOFF`).
    Inputs that used `GRID` or `MATRIX` stopped with "keyword ARG is compulsory for this action", because `ARG` was read before the old keyword.
  - A PDB file with a field that cannot be read (e.g. a misaligned line) and a grid file without the column of the bias (e.g. written by an action with another label)
    gave an assertion that did not say where the problem was: the errors now show the line of the PDB file, or the file and the columns of the grid.
  - `ARG=*` (e.g. `PRINT ARG=*`) leaves out the values that the action cannot use: values of a type it does not accept, and vectors of which only some elements are computed
    (e.g. the pairs of strands of [PARABETARMSD](PARABETARMSD.md) with `STRANDS_CUTOFF`). The number of values left out is written in the log.
  - The [PLUMED](PLUMED.md) action passed the step to the guest instance as an `int`: steps above $2^{31}$ were negative in the guest.
  - With `--parse-only` (as in the PLUMED-NEST and tutorial sites) the checks that need the inputs of all the replicas are skipped: [SHADOW](SHADOW.md) without `REFERENCE`
    and [MAXENT](MAXENT.md) with one `APPLY_WEIGHTS` per replica of the full run stopped with an error when the input of one replica was read alone. The checks are kept in a run.
  - The environment variable `PLUMED_NONFINITE_ACTION_TRACE` (a list of action labels, or `*`) checks the values, derivatives and forces of the selected actions at every step,
    and reports the step, the action and the element where a `nan` or `inf` first appears. It adds a considerable overhead.

#### Command line tools, driver and installation

  - `pip install plumed` now installs, on Linux (x86_64 and aarch64), macOS (arm64 and x86_64) and Windows (x86_64), the python interface together with a PLUMED kernel, so that no separate PLUMED installation is needed:
    - The Python interface and its bundled runtime share the `plumed` package: the compiled extension is `plumed._plumed` and runtime files are under `plumed/runtime`, avoiding a separate top-level `plumed_runtime` package. Public imports such as `plumed.Plumed` and `plumed.InputBuilder` are unchanged.
    - InputBuilder, metadata parsing and data-file utilities are implemented in Python modules, while the native `Plumed` command interface remains compiled. Their public imports and calling conventions are preserved.
    - Python data-file utilities close files they open on success and errors while keeping caller-owned streams open. Chunked readers support explicit closure and context managers. Legacy InputBuilder root discovery propagates interrupts instead of swallowing them.
    - The kernel includes the default modules and does not use MPI, OpenMP or external blas, lapack, fftw and zlib.
      It includes HDF5 (tables in `.h5` files) and chemfiles (driver `--itraj`, GROMACS `.tpr` files in MOLINFO), linked statically:
      the kernel does not export their symbols, so it can be used together with other copies of them (e.g. the HDF5 of `h5py`).
      `python/build_dependencies.py` builds these libraries, and `PLUMED_DEPENDENCIES` tells the build of the package where they are.
      The CMake build has the options `PLUMED_ENABLE_HDF5` and `PLUMED_ENABLE_CHEMFILES`.
    - The `plumed` command is installed too, including [LOAD](LOAD.md) and `plumed mklib` to compile your own actions (a C++ compiler is needed).
    - A different kernel can still be used, by setting `PLUMED_KERNEL` or with `plumed.Plumed(kernel=path)`. An invalid explicit path is an error, it does not fall back to the bundled kernel.
    - Building from the source distribution (`pip install --no-binary plumed plumed`) compiles the same kernel. Packagers who want only the python interface can set `PLUMED_BUILD_KERNEL=0`.
    - Windows wheels (x86_64) contain a kernel built with CMake and Visual Studio (`plumedKernel.dll`, linked with the static C++ runtime so that no Visual C++ redistributable is needed)
      and `plumed.exe`. There, [LOAD](LOAD.md), `plumed mklib` and the commands implemented as shell scripts (e.g. `plumed config`) are not available.
      The CMake build has the option `PLUMED_PIP_BUNDLE` for this kernel, and its installation now also contains `config.txt` and the vim and json syntax files.
  - `plumed.InputBuilder` reads the list of actions and keywords directly from the selected kernel (new commands `getInputBuilderJSONLength` and `getInputBuilderJSON`),
    so it works without the `plumed` executable, the vim files or the source tree. Numbered keywords (e.g. `KAPPA0`, `KAPPA1`, ...) are now identified exactly.
    With kernels from previous versions the vim files of their installation are used, as before.
  - New command `plumed gen_vim`, which writes the Vim syntax and help files of all the registered actions in a single run.
    It is used by `make` and when building the python wheels, instead of calling `plumed manual --vim` once per action.
  - `plumed mklib`, which is also used by [LOAD](LOAD.md) to compile `.cpp` files, now passes the PLUMED kernel and the libraries in `PLUMED_MKLIB_LDFLAGS` after the object files.
    Linkers using `--as-needed` (the default e.g. on Ubuntu) dropped them, so that the compiled libraries did not depend on the kernel and could not be loaded with [LOAD](LOAD.md) from the python interface (undefined symbols).
  - Fixes in the command line tools:
    - [driver](driver.md): the single precision version (`driver-float`, or `--debug-float yes`) stopped at the first frame;
      a trajectory file that cannot be opened made driver and [benchmark](benchmark.md) crash; reading xtc and trr
      trajectories from standard input is now an error (it was a crash); clear errors for a wrong `--box`, an atom index out of range in the `--mc` file
      and a `--dump-forces` file that cannot be opened.
    - [simplemd](simplemd.md): the forces were wrong when `sigma` is not 1; with `temperature NVE` (the default) the initial velocities
      and the thermostat used uninitialized values (now the atoms start at rest and there is no thermostat); `nconfig` and `nstat`
      without a file name used a random file name (the defaults are now `10 trajectory.xyz` and `1 energies.dat`).
      The neighbor list is built with linked cells when the box is large enough (with 4096 atoms a run is 6 times faster, with identical results),
      and results with OpenMP no longer depend on the timing of the threads.
    - [pesmd](pesmd.md): `temperature NVE` used uninitialized values; the energy of the thermostat in `stats.out` was wrong with more than three dimensions;
      the final jobs were not run (e.g. a [DUMPGRID](DUMPGRID.md) with `STRIDE=0` wrote nothing). The `friction` keyword is the relaxation time of the thermostat (as before; the documentation said friction).
    - [plotswitch](plotswitch.md) never ended with `--centerrange`; the table is written on the output of the tool and its points pass through R_0.
    - [pdbrenumber](pdbrenumber.md): with several models, the numbering restarted from 0 after each `ENDMDL` instead of from the first number.
    - Tools reading an input file (e.g. [simplemd](simplemd.md), [pesmd](pesmd.md)): a flag missing from the file made them crash, lines longer than 255 characters were split,
      and an unknown keyword gave exit code 0. Errors in the input of a tool now give a message and exit code 1 instead of an abort.
    - [benchmark](benchmark.md) with `--domain-decomposition` stopped with an error when run with `plumed --no-mpi` in a build with MPI.
      With `--shuffled` or `--domain-decomposition` the positions were not moved with the atoms, so that PLUMED saw a different, permuted structure
      (which also depended on the C++ library, since `std::shuffle` is implementation defined).
    - Smaller fixes in [gen_example](gen_example.md), [gen_json](gen_json.md) and [show_graph](show_graph.md).
  - PLUMED can be built natively on Windows with Microsoft Visual C++, using CMake (`CMakeLists.txt`, static kernel); the build is tested in the CI.
  - With `-DPLUMED_SHARED_KERNEL=ON` the CMake build makes a shared kernel (`plumedKernel.dll` on Windows) and links the `plumed` executable to it.
    Only its C entry points are exported (`cmake-msvc/plumedKernel.def`). `Plumed.h` loads the kernel at runtime on Windows too (with `LoadLibrary`),
    so that `PLUMED_KERNEL` and `plumed_create_dlopen` can be used with this DLL when the wrapper is compiled with `__PLUMED_HAS_DLOPEN`.
  - The python interface can be installed on Windows (`pip install python/` with `plumed_default_kernel` pointing to `plumedKernel.dll`, or with `PLUMED_KERNEL`).
    Integer `numpy` arrays of type `np.int_` (64 bit also on Windows with numpy 2) are passed correctly, and `write_pandas` writes `\n` line endings on all platforms.
    The Windows null device (`NUL`, e.g. `os.devnull` in python) can be used as an output file, as `/dev/null`. `LOAD` and MPI are not available there yet.
  - The CMake build enables the same modules as `./configure` (read from the `module.type` files), compiles lepton expressions with the embedded asmjit
    on x86-64 and 64 bit ARM (as `./configure` does; option `PLUMED_ENABLE_ASMJIT`), and on Windows prints stack traces with `PLUMED_STACK_TRACE=yes`
    (names and lines need the debug information, see `PLUMED_MSVC_DEBUG_INFO`).
  - `PLMD::Exception` objects are smaller (the stack trace and the formatting stream are allocated on the heap): with MSVC each of them took more than 1 kB
    of the stack frame of `PlumedMain::cmd`, so that nested `cmd` calls (`DEBUG logRequestedAtoms`, the [PLUMED](PLUMED.md) action) overflowed a 1 MB stack.
  - On Windows, file names are UTF-8 strings (as the python interface passes them) and can contain any character: the kernel converts them to UTF-16 when it opens,
    renames or checks files, and `plumed.exe` uses UTF-8 as its code page (Windows 10 version 1903 or later). Before, names were read in the ANSI code page,
    so that from python any non-ASCII character failed. Files opened directly by some contributed modules still use the ANSI code page.
  - A PLUMED kernel built without MPI can use MPI at run time: an MD code can pass it its own MPI implementation (as the GROMACS 2026 patch does), a provider library
    can be selected through the environment, and the command line tools can run on several threads with the embedded thread-MPI of GROMACS (`--tmpi-threads N`).
    `plumed --has-mpi`, `--has-real-mpi` and `--has-thread-mpi` say what is available. The conda package `plumed` is built without MPI, and small `plumed-mpi` packages
    add the providers for MPICH and Open MPI (see `src/mpiwrap/README.md`). Conda packages are also built for Linux on ARM64.
  - The GROMACS 2025 and 2026 patches tell PLUMED about a checkpoint before the force calculation of the step (needed by [CHECKPOINT](CHECKPOINT.md)).
  - The GROMACS patches (2024.3, 2025.0, 2026.0) do not reset the GPU at the end of a run with `-plumed`, as GROMACS already does with Torch: the GPU runtime of a plugin
    (e.g. the OpenACC one of `plugins/openaccPTM`) frees its memory at process exit, and failed with `CUDA_ERROR_CONTEXT_IS_DESTROYED` after the reset.
  - [driver](driver.md) has `--log-file`, to write the PLUMED log on a file instead of the standard output (with `--multi`, one file per replica, so that the logs of the replicas are not mixed).
  - [benchmark](benchmark.md) can scale the distances between the atoms of its synthetic configurations (the base distance is 1).
  - The environment variable `PLUMED_LOG_FILE` sets the name of the log file when running with GROMACS (it was always `PLUMED.OUT`).

### Changes relevant for developers:

  - `PLMD::Random` uses xoshiro256** (state of four 64-bit integers). `RandInt(n)`, which was declared but not defined, returns a uniform integer in `[0,n)`; `RandUInt64(n)` is the 64-bit version.
    `Shuffle` takes a vector of any type. `U01()` returns numbers in the open interval (0,1) with 53-bit resolution; `U01d()` is the same as `U01()` and `IncreasedPrecis()` has no effect.
    The strings of `toString()`, `stateToString()` and `operator<<` start with the name of the engine, and reading a state of the previous engine is an error.

  - `src/molfile` was removed. `TrajectoryParser::init()` no longer has the `useMolfile` and `command_line_natoms` arguments, `TrajectoryParser::getMolfilePluginsnames()`
    is replaced by `deprecatedOptions()` and `removedOptions()`, `Tools::molfile_lock()` was removed, and `__PLUMED_HAS_MOLFILE_PLUGINS` is no longer defined
    (`plumed config has molfile_plugins` and `plumed --has-molfile` answer no).
  - `TrajectoryParser::init()` and the constructor of `fileTraj` take the chemfiles format as an optional third argument, used with the format `traj` (`--itraj`);
    `__PLUMED_HAS_LIBCHEMFILES` is defined when PLUMED is configured with `--enable-libchemfiles`.
  - `Plumed.h` can generate a host MPI adapter with `__PLUMED_WRAPPER_MPI_HOST_ADAPTER=1`.
    Command API 13 accepts `injectMPIImplementation` for MPI-independent kernels, shared by all objects in the loaded kernel; the symbol table stays at version 4.
    Descriptor data are copied, provider code stays borrowed, and compatible repeated injections retain the first installed table.
    C11 communicator checks default on; C++ checks default to the optional anonymous-namespace mode so shared wrapper classes are consistent across translation units.
    Python ordinary values now carry communicator exclusion metadata while recognized mpi4py communicators retain their existing path.

  - `CheckpointWriter`/`CheckpointReader` (`tools/Checkpoint.h`): a minimal binary container (named, typed entries in nested sections, little-endian, CRC32) used by the
    [CHECKPOINT](CHECKPOINT.md) file. Actions with an internal state override `Action::hasCheckpointState()`, `writeCheckpoint(CheckpointWriter&)` and `readCheckpoint(CheckpointReader&)`;
    `PlumedMain::checkpointing` (`core/Checkpointing.h`) writes the file at the start of the step, before `prepareDependencies`, and restores it at the first step after a restart.
    `OFile` registers every file opened for writing so that its size can be recorded and trimmed.
    `GridBase::writeCheckpoint`/`readCheckpoint` store and restore a grid bitwise (range, spacing, values and derivatives, dense or sparse);
    `Bias::writeComponentValues`/`readComponentValues` the values of the components; `FlexibleBin` its statistics.
    `Random::stateToString`/`stateFromString` store the complete state of a generator, including the cached Gaussian number
    (`toString`/`fromString` keep only the uniform generator and are not exact for `Gaussian()`).
  - The manual page of [LOAD](LOAD.md) lists the changes that are usually needed to compile code written for older versions of PLUMED
    (Atoms.h, Communicator.h, `componentsAreNotOptional`, `addOutputComponent` with three arguments, the old multicolvar classes).
  - Helper functions of `PDB`, `Grid`, `RMSD`, `HistogramBead` and `KernelFunctions` that PLUMED did not use were removed (about 750 lines);
    the list, with the replacements, is on the manual page of [LOAD](LOAD.md).

  - The type of each value and component that an action creates is now checked against the type declared with `setValueDescription` and `addOutputComponent`.
    The check (`Keywords::componentHasCorrectType`) combined the types with `|`, so it was always true, and it threw `std::out_of_range` for an undocumented value.
    An undocumented or wrongly documented output now stops with an error that names the action and the output.
    Fixed declarations: `struct` of the secondary structure actions (vector), the value of PAIRENTROPIES (grid), ONES (also matrix), SELECT_COMPONENTS (also scalar), MFILTER_MORE (vector, was missing).

  - `ActionSet` keeps an index of its actions, so that `selectWithLabel`, `getShortcutActionWithLabel`, `selectLatest<GenericMolInfo*>` and `ActionAtomistic::getAtomValuesFromPlumedObject`
    do not scan all the actions anymore. The index is extended with the actions appended to the set since the last lookup (actions must only be appended, as `PlumedMain` does)
    and is rebuilt if the set is cleared. New methods `ActionSet::getAtomValues` and `ActionSet::getNumberOfActionsForInterface`.
  - `Tools::getline(FILE*)` returns the last line of a file also when it does not end with a newline (it was lost).
    `CLToolMain` catches the exceptions thrown while reading the input of a command line tool. The default `fileParser::init(FILE*)` of
    `TrajectoryParser` returns an error for the formats that cannot be read from a stream.
  - The bound check in `Value::get` was never compiled (`#ifdef DNDEBUG`): it is now active in debug builds.
  - `LeptonCall` can be copied safely (copies pointed to the variables of the original expressions).
  - `FunctionOfVector` evaluates the function at zero arguments when it is constructed; elements whose arguments are all zero are skipped only if the result is zero (`function::functionIsZeroWhenArgumentsAreZero`).
  - `LinkCells` does not use its communicator anymore (the constructor argument is kept for compatibility). `IFile::getline` reads lines in chunks. `Communicator` frees the communicators obtained with `Split` and handles `Set_comm(MPI_COMM_SELF)`; its copy constructor does not read an uninitialized communicator.
  - Faster build and installation:
    - Each source file is now compiled only once (the second compilation, which was left over after the dependency files started to be generated by the compiler itself, has been removed), and dependency files are written directly in `deps/`.
    - The python interface (both the one in `python/` and the one built during `make install`) is not rebuilt anymore at every `make`/`make install`, but only when its sources or the configuration change.
    - `make install` does not build anymore the python interface in `python/`, since the installed one is built separately against the installed kernel.
    - The files generated by running plumed (`vim/syntax`, `vim/help`, `json/syntax.json`) are regenerated only when the plumed executable changes.
    - With `make -j`, the python interface is now built concurrently with the C++ code, and the libraries in `src/lib` and in `src/lib/install` are linked concurrently.
    - The python interface is compiled from the committed `python/plumed.c`, so building it does not require cython and does not modify tracked files anymore. `plumed.c` is regenerated from `plumed.pyx` and `cplumed.pxd` only when they change (or with `make -C python cythonize`), and must then be committed; its consistency is checked in the CI.
  - `Subprocess` launches the command in a new process group and sends the signals to the whole group, so that they also reach the processes started by the shell.
    `Subprocess::stop()` and `Subprocess::cont()` (enabled with `PLUMED_ENABLE_SIGNALS`) now actually stop and resume these processes.
    When a `Subprocess` is destroyed, the group receives `SIGTERM` (and `SIGCONT`, in case it was stopped) and, if the shell has not exited after one second, `SIGKILL`.
  - `TrajectoryParser` (`tools/TrajectoryParser.h`, used by the driver and the benchmark): `readHeader`, `readAtoms` and `readFrame` take a `TrajectoryFrame<real>`
    (the buffers, the options and the step, time step and time read from the file) instead of ten arguments, and the readers are written once, in double precision,
    instead of twice (float and double). The xdrfile reader keeps its buffer between frames. `xdrfile_decompress_coord_float_long` and `xdrfile_compress_coord_float_long`
    read and write the size of the compressed data as a 64 bit integer (xtc magic number 2023); the buffers of the xdrfile compression are freed when they grow (they were leaked).
  - The `xdrfile` module is now always compiled: since the trajectory parser was moved to `src/tools` it requires it, and configuring with `--enable-modules=none` (or removing it) failed at link time.
  - The core module does not call blas directly anymore: the only call (a `daxpy` used to sum the forces in `ActionWithValue`) has been replaced by a plain loop, which is as fast and avoids calling a threaded blas within an OpenMP region. The configure warnings printed when the internal blas/lapack are used have been reworded, since the internal versions are only slower than an optimized external library with large matrices.
  - `pseudoInvert` builds the pseudoinverse with a single product, without the intermediate dense matrices; the result is the same and it is up to 2 times faster for large matrices. `diagMatRange` computes only a range of the eigenvalues and eigenvectors of a symmetric matrix.
  - Input lines are parsed using a dictionary instead of an array, which speeds up the parsing of very long input lines.
  - The `AtomDistribution` functionality of the benchmark is now a separate class (`tools/AtomDistribution.h`) that can be used in tests or in other tools.
  - It is not possible anymore to register lowercase keywords and the developer must always specify the keywords completely as uppercase while parsing in the action constructor. There are no differences for the user, apart from the entry in the manual for the DEBUG action: the user can still specify lowercase and mixed case keywords in the input file.
  - Plugins:
    - The plugins have a common directory structure.
    - They are checked with codecheck.
    - They are formatted by the `astyle` target of the main directory.
    - They are **not** cleaned by `make clean` in the main directory.
  - With `--enable-rpath`, if the linker writes `RPATH` by default (older toolchains), `configure` now adds `-Wl,--enable-new-dtags` so that `RUNPATH` is used. With `RPATH` the executables of the build tree loaded the kernel installed in the target directory (if any) instead of their own one, even after sourcing `sourceme.sh`: for instance the build failed with `unknown command gen_vim` when an older version was installed there.
  - Removed the optional `--enable-boost_graph` configure option and the `__PLUMED_HAS_BOOST_GRAPH` macro. The Boost branch of [DFSCLUSTERING](DFSCLUSTERING.md) was disabled by default, no longer compiled against the current code, and not tested in the CI; the built-in depth first search is now always used.
  - A new CI workflow checks the python interface and the `pycv` plugin with several python versions.
  - Part of the python scripts are checked for errors and formatting in the CI, with the ruff python package;
    the `astyle` target of the main Makefile formats the python scripts when ruff is found.
  - Python packaging:
    - Bundled runtimes follow the normal installed layout inside the Python package: resources in `runtime/lib/plumed` and headers in `runtime/include/plumed`. The shared kernel discovers both relative to its library, and the wheel includes the standard main source needed by `plumed mkmpi --executable`.
    - `python/pyproject.toml` and `python/build_backend.py` (a PEP 517 backend wrapping setuptools) build the wheels with the bundled kernel, using `configure` and `make`.
      The output of the kernel build is shown only if it fails (`PLUMED_BUILD_VERBOSE=1` shows everything), and with `PLUMED_RUNTIME_CACHE` the kernel is built once and reused for all the python versions.
    - The `Python package` workflow builds the source distribution and, with cibuildwheel, the wheels for CPython 3.11 to 3.15 (manylinux2014 and macOS), tests the installed wheels with `python/test/test_bundled_wheel.py`,
      and publishes them with PyPI Trusted Publishing when a `v*` tag is pushed (or to TestPyPI when started by hand).
    - The consistency of `python/plumed.c` is checked with `python/compare_plumed_c.sh`, which ignores the compressed copies of the strings that cython (>=3.1) generates, since they depend on the python version and on the compression libraries used to run cython.
  - The CI also runs every night on the master branch, and can be started by hand from the Actions tab.
  - A regtest can be marked as long with `plumed_long=yes` in its config: it then runs only when `PLUMED_LONG_TESTS=yes`, as in the nightly CI run, and not on pull requests.
  - New CI jobs build all the modules and run the regtests with AddressSanitizer and UndefinedBehaviorSanitizer, with clang without OpenMP (any warning of `-Wall -Wextra` in PLUMED code fails the job, see `.ci/check-warnings`), and with `--disable-dlopen`.
    The regtests that need `dlopen` declare `plumed_needs=dlopen`.
  - CI fails when an example of the manual that worked stops working: the pages with known failures are listed in `new-manual/broken-examples.allowed`, a list that should only shrink.
  - `src/gemmi` is a copy of the CIF parser of gemmi 0.7.5 (`cif.hpp` and the headers it includes, among them PEGTL), imported with `src/gemmi/import.sh` and never edited by hand;
    the script puts the namespaces `gemmi` and `tao` inside `PLMD` (`PLMD::gemmi`, `PLMD::tao`), so that the copy cannot clash with another gemmi in the same program (e.g. the one bundled in chemfiles).
    PLUMED includes it only through `gemmi/cif.h`, which treats it as a system header. `PDB` has getters for the insertion code and the element of an atom, residue lookups that take an insertion code
    (`"*"` matches any), `getAdjacentResidue` and `getResidueIdsInChain`; `PDB::read` takes the numbering of the atoms (`PDB::AtomNumbering`); `MolDataClass::baseResidueName`.
  - `.ci/audit-inputs.py` runs the examples of the manual and variants of them (a keyword removed, a number set to 0 or -1, a list cut to one element) and reports the inputs that crash PLUMED or stop it with an assertion instead of an error message; `.ci/audit-keywords.py` reports the registered keywords that the code of an action never reads.
  - `Action::getkBT()` must be called in the constructor (it reads `TEMP` from the keywords, which exist only there): a later call stops with a message.
  - `Action::getNumberOfReplicas()` and `Action::getReplicaIndex()` give the number of replicas and the index of the replica on every rank of a replica
    (`multi_sim_comm` is valid only on the first rank; in debug builds, using it on the other ranks is an error).
  - An optional CI workflow, started by hand, builds GROMACS, LAMMPS and sander with PLUMED and checks MPI injection and the forces.
