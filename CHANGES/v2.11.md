## Version 2.11 (under development)

This page contains changes that will end up in 2.11

### Changes relevant for users:

  - Updated the embedded Lepton and AsmJit libraries from OpenMM 8.6.1, preserving PLUMED-specific expression functions and semantics. Just-in-time compilation of [CUSTOM](CUSTOM.md) expressions and custom switching functions now supports AArch64, including Apple Silicon, and is enabled by default on supported architectures. It can be disabled with `./configure --disable-asmjit` or at runtime with `PLUMED_USE_ASMJIT=no`.

  - When using [MOLINFO](MOLINFO.md) with the `WHOLE` flag, PBCs in the following actions will be reconstructed using a minimum spanning tree based on the coordinates stored in the MOLFILE reference pdb.
  - When using the benchmark now it is possible to scale the atom distances in the synthetic atom distribution (the base atomic distance is 1)
  - [SAXS](SAXS.md) now accepts the `MARTINI_FF` keyword to select the Martini form-factor generation: `MARTINI_FF=2` (default) keeps the existing Martini 2.2 protein and nucleic-acid form factors, while `MARTINI_FF=3` selects Martini 3 protein form factors.
  - [SAXS](SAXS.md) includes bug fixes related to the `ONEBEAD` approach and nucleic acid in some corner case, as well as general improvements in performances and SANS calculation. 
  - [SAXS](SAXS.md) includes new ions parameters that can be used both in `ATOMISTIC` and `ONEBEAD` modes.
  - [METAINFERENCE](METAINFERENCE.md) includes stability fixes when restarting while parameter optimisation is running.
  - Added environment variable `PLUMED_LOG_FILE` to control the log file pathname when running with GROMACS (the log file was hardcoded as `PLUMED.OUT`)
  - Changed CUTOFF keyword in [DISTANCE_MATRIX](DISTANCE_MATRIX) to LINKCELL_CUTOFF to make the purpose of this keyword clearer.
  - The kernels of [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) are now force-shifted at KERNEL_CUTOFF, so that both their value and their derivative go to zero at the cutoff.
    Previously they were energy-shifted: their value went to zero at the cutoff, but their derivative jumped to zero there (see [#1463](https://github.com/plumed/plumed2/pull/1463)).
    Bias values and kernel heights change only in the far tails of the kernels, and forces change slightly, mostly early in a simulation.
    The script `FES_from_State.py` of the OPES tutorial uses the new kernels.
  - [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) now use their neighbor list by default, since it is exact and never slower; it can be switched off with NLIST_OFF.
    The NLIST flag is still accepted, and only adds the `nlker` and `nlsteps` components as in previous versions.
    The NLIST_PACE_RESET flag is removed: with WALKERS_MPI, the neighbor list is now always reset after each deposition.
  - Positions and forces are shared with the MD code faster. The lists of the atoms needed by the actions are rebuilt only when they change,
    also when an MD code with domain decomposition passes the same local atoms at every step; the choice between copying all the atoms
    and copying only those that are needed (`PLUMED_FORCE_UNIQUE=auto`) is based on all the atoms needed by the active actions instead
    of on the largest single action; OpenMP threads are only used for large copies.
    With `plumed benchmark`, 7000 atoms and three [COORDINATION](COORDINATION.md) between one atom and 2207 atoms, "Sharing data" went
    from 82 to 7 microseconds per step in serial and from 84 to 25 microseconds with domain decomposition on two ranks.
  - Actions with a neighbor list (e.g. [COORDINATION](COORDINATION.md) with `NLIST`) request the reduced list of atoms only once after
    each update of the list, instead of at every step: requesting the same atoms made PLUMED rebuild the lists of atoms at every step.
  - [FIT_TO_TEMPLATE](FIT_TO_TEMPLATE.md) and [RESET_CELL](RESET_CELL.md), which move all the atoms, are 2 to 5 times faster: they loop
    directly on the arrays of positions and forces. With `plumed benchmark`, 7000 atoms and `TYPE=OPTIMAL` with 200 aligned atoms,
    FIT_TO_TEMPLATE went from 148 to 90 microseconds per step for the positions and from 260 to 48 for the forces. The results are identical.
  - The forces on the eigenvectors computed by [DIAGONALIZE](DIAGONALIZE.md) (used e.g. when biasing [SPRINT](SPRINT.md)) are computed in a time that scales
    as N^2 instead of N^4 with the size N of the matrix. With a 200x200 contact matrix, applying the forces went from 5 seconds to 0.3 milliseconds per step.
  - The iterations of the SMACOF algorithm (used by [ARRANGE_POINTS](ARRANGE_POINTS.md) with `MINTYPE=smacof` and by [SKETCHMAP](SKETCHMAP.md) with `USE_SMACOF`) scale as M^2 instead of M^3 with the number of points M: with 1000 points an iteration went from 3 seconds to 6 milliseconds.
  - Symmetric positive definite matrices (e.g. the covariance matrices of multivariate Gaussians) are inverted with a Cholesky factorization instead of being diagonalized,
    which is 5 to 25 times faster for matrices with up to 10 rows and about 4 times faster for large matrices; matrix products are 2 to 5 times faster.
    [METAD](METAD.md) with `ADAPTIVE=DIFF` and three CVs depositing a Gaussian at every step is about 20% faster, and reading 20000 multivariate Gaussians when restarting is about 25% faster.
  - When no derivatives are needed, [DIAGONALIZE](DIAGONALIZE.md) computes only the requested eigenvalues and eigenvectors (from the largest one down to the smallest requested one) instead of all of them.
    With `VECTORS=1` this is 3 to 4 times faster: e.g. for a 1000x1000 contact matrix it went from 180 to 70 milliseconds per frame. [CLASSICAL_MDS](CLASSICAL_MDS.md) also benefits: with 2000 frames the analysis is about 20% faster.
    The results are identical.
  - PLUMED stops with an error, instead of crashing, when it has to apply forces on the atoms or on a value passed with [PUT](PUT.md)
    and the MD code did not pass the array for these forces. The size of the arrays passed with domain decomposition is now checked
    also when PLUMED is compiled without debug flags.
  - [METAD](METAD.md) and [PBMETAD](PBMETAD.md) have been revised; PBMETAD now uses the grids, kernels and hills files of METAD. Results change in the following cases:
    - Grids are extended automatically when a Gaussian does not fit in them (GRID_MIN and GRID_MAX give the initial range; GRID_SIZE_LIMIT sets the maximum number of points); GRID_SPACING can be given without GRID_MIN and GRID_MAX. A grid read with GRID_RFILE(S) can have any range on the lattice of the grid in input.
    - No Gaussian is added at the first step of a simulation; when continuing a simulation, a Gaussian is added at the first step unless the hills file already contains it (also when restarting from a grid, see [#267](https://github.com/plumed/plumed2/issues/267)). PBMETAD never added a Gaussian at the first step of a run.
    - ADAPTIVE=DIFF: when restarting, the statistics of the fluctuations are initialized from the last hills of the hills file (DIFF_FROM_SCRATCH restores the old behavior); with replica exchange the running average is restarted when an exchange is accepted, instead of stopping with an error ([#26](https://github.com/plumed/plumed2/issues/26)); PRECAL_DIFF accumulates the statistics also outside the update window ([#1328](https://github.com/plumed/plumed2/issues/1328)).
    - An incomplete last line of the hills file (an interrupted run) is removed when restarting ([#727](https://github.com/plumed/plumed2/issues/727)).
    - PBMETAD uses stretched Gaussians, as METAD and as written in its hills files (biases change by about 0.2%); it requires the temperature (TEMP); partitioned families with ADAPTIVE and families in a different order than the arguments are fixed.
    - INTERVAL with a grid: beyond the limits the force is zero also within the grid cell that contains a limit; with NLIST the neighbor list is built at the limit.
    - Multiple walkers: the hills files are read by the first MPI process of each walker and broadcast (with several processes per walker the run could hang); restarting from the grid of a walker (WALKERS_N) adds only the hills of the other walkers that are not in the grid (their number is written in a comment after the grid); the hills and grid files are read without the replica suffix, as they are written.
    - Grids are filled with OpenMP and are faster also without OpenMP; the c(t) reweighting factor (CALC_RCT) is fixed with GRID_SPARSE; ACCELERATION and FREQUENCY_ADAPTIVE are restarted correctly.
    - PBMETAD: BIASFACTOR=1 means, as in METAD, that no bias is applied and the hills files and grids contain the estimate of -F (TAU can be given instead of HEIGHT); new PRECAL_DIFF and STORE_GRIDS keywords, as in METAD.
    - Inputs that crashed or gave meaningless results are now errors (e.g. WALKERS_RSTRIDE=0, negative SIGMA, HEIGHT or TAU, ADAPTIVE on a grid without SIGMA_MIN also in PBMETAD and when reading a grid in METAD, a SELECTOR that is not defined in PBMETAD).
  - [sum_hills](sum_hills.md) has been revised:
    - variables whose name contains `sigma_`, `time`, `min_` or `max_` are found correctly (they made it crash, [#1226](https://github.com/plumed/plumed2/issues/1226)); `--spacing` can be used without `--min` and `--max`; `--negbias` is correct also when the run was not well tempered; with MPI the derivatives were zero.
    - `--sort time` (or `clock`) merges the hills files of multiple walkers in order of time, so that the free energies written with `--stride` follow the simulation ([#1351](https://github.com/plumed/plumed2/issues/1351)).
    - `--average` computes the time average of the bias, and `--basins` writes the free-energy differences between basins at each output, to check convergence.
    - The hills are summed several times faster (the Gaussians are computed as products over the variables), and with MPI the grids are summed once per output.
    - The documentation has been rewritten. It now states that `--histo` does not reweight the points, and shows how to compute a free energy from a biased simulation with [driver](driver.md), [REWEIGHT_BIAS](REWEIGHT_BIAS.md) and [HISTOGRAM](HISTOGRAM.md).
  - The examples in the documentation of [HISTOGRAM](HISTOGRAM.md), [REWEIGHT_BIAS](REWEIGHT_BIAS.md), [REWEIGHT_METAD](REWEIGHT_METAD.md) and [METAD](METAD.md) that use `LOGWEIGHTS` now set `NORMALIZATION`, without which HISTOGRAM stops with an error.
  - [METAINFERENCE](METAINFERENCE.md) and the ISDB collective variables with `DOSCORE` ([NOE](NOE.md), [PRE](PRE.md), [RDC](RDC.md), [JCOUPLING](JCOUPLING.md), [CS2BACKBONE](CS2BACKBONE.md), [SAXS](SAXS.md)) now share one implementation of Metainference. Results change in the following cases:
    - New SEED keyword to make the Monte Carlo sampling of the uncertainties, scale, offset and ftilde reproducible (by default the seed is still taken from the clock).
    - SELECTOR and NSELECT were ignored by the collective variables with `DOSCORE` (the history of sigma mean and the averaged weights were always those of the first selector value); they now work as in METAINFERENCE.
    - With `DOSCORE` and RESTART, a missing status file was created empty and then read as a restart (averaged weights starting from zero); it is now a new start, as in METAINFERENCE.
    - NOISETYPE=GENERIC could not be restarted (ftilde was not read back from the status file).
    - OPTSIGMAMEAN with a single replica gave NaN after AVERAGING steps: the standard error of the mean is not defined with one replica, and sigma mean now keeps its initial value.
    - Monte Carlo moves larger than the allowed interval (DSIGMA, DSCALE or DOFFSET larger than the range of the flat prior) could leave the interval; with NOISETYPE=GENERIC and OPTSIGMAMEAN, sigma could move above SIGMA_MAX when sigma mean exceeded it (it is now kept equal to sigma mean, with a warning).
    - More than one DSIGMA with NOISETYPE=GAUSS or OUTLIERS is an error, as for SIGMA0, SIGMA_MIN and SIGMA_MAX.
    - Moves of chunks of sigmas (MC_CHUNKSIZE) and of ftilde are computed from energy differences, and the history of sigma mean (OPTSIGMAMEAN with AVERAGING) no longer grows in cost with AVERAGING. NOE, PRE, RDC and JCOUPLING no longer look up their components by name at every step (with 3000 NOEs and `DOSCORE` a step went from 24 to 1.7 ms).
  - Bug fixes and performance improvements in the other ISDB actions. Results change in the following cases:
    - [CALIBER](CALIBER.md): with SCALE different from 1 or with REGRES_ZERO the forces were not the derivatives of the bias (they were divided instead of multiplied by the scale). The data file is checked (it was read with a duplicated last line), its first time is no longer assumed to be zero, and a simulation time outside the data is an error.
    - [CS2BACKBONE](CS2BACKBONE.md): the non-bonded term excluded the residues adjacent in sequence without looking at the chain, so with chains numbered from 1 the contacts between residues with close numbers in different chains were dropped. ATOMS and TEMPLATE must now contain the same atoms (they were silently assumed to be numbered from 1 in the same order). With MPI less data are communicated.
    - [EMMI](EMMI.md): with REWEIGHT the forces and the derivative with respect to the bias were wrong when the weights of the replicas were different; atoms with the same tabulated overlap could be dropped from the neighbor list. New SEED keyword. With MPI the derivatives of the overlaps are no longer summed at every step; OpenMP parallelization; the scale regression is done once instead of on every rank and replica.
    - [EMMIVOX](EMMIVOX.md): new SEED keyword; the neighbor sphere uses a cell list (it was O(voxels x atoms)); results no longer depend on the number of OpenMP threads; the score is summed in double precision.
    - [SAXS](SAXS.md) and [SANS](SANS.md): faster Debye sums (sine and cosine for all the q values by angle addition), with `DOSCORE` only the contracted derivatives are summed over the MPI ranks, faster SASA for ONEBEAD, blocks of particles on GPU. With SIGMARES the self term of the intensity is now smeared too. The random deuteration of SANS is drawn by the first rank with PLUMED's own generator.
    - [JCOUPLING](JCOUPLING.md) with `DOSCORE` now sets the j-# components (they were always zero); [RDC](RDC.md) with `DOSCORE` no longer allocates derivatives for each coupling.
    - [RESCALE](RESCALE.md) uses PLUMED's random number generator and has a SEED keyword; [SELECT](SELECT.md) and RESCALE stop if the SELECTOR does not exist; [SHADOW](SHADOW.md) checks that exactly one replica uses REFERENCE; [BAIES](BAIES.md) checks that the atoms in DATA_FILE are in ATOMS.

  - [JCOUPLING](JCOUPLING.md) with `TYPE=CUSTOM` used uninitialised Karplus parameters when A, B or C were not given; A, B and C are now compulsory with `TYPE=CUSTOM`, and SHIFT is zero by default.

  - [UPPER_WALLS](UPPER_WALLS.md) and [LOWER_WALLS](LOWER_WALLS.md) acting on periodic arguments do not apply periodic boundary conditions to the difference between the argument and AT anymore
    ([#658](https://github.com/plumed/plumed2/issues/658)). Previously each wall acted on half of the periodic domain, so that e.g. an upper and a lower wall at $\pm 2$ on a torsion
    pushed it out of the interval $[-2,2]$ when its value was beyond $\pm(\pi-2)$. AT must now be within the periodic domain of the argument.
    Results are unchanged when the argument stays further than half a period from AT.
  - [MOLINFO](MOLINFO.md) selectors based on a python interpreter (`@mda:`, `@mdt:`, `@vmd:` and `@vmdexec:`) now terminate the interpreter, and the processes it starts (e.g. `vmd`),
    when PLUMED finishes. Previously only the shell used to launch the interpreter was signaled, so that the temporary file created by the selector script could be left behind
    and processes that did not exit when their input was closed could be left running.

  - Fixes and speed-ups in the tools used by many actions:
    - Neighbor lists of [COORDINATION](COORDINATION.md) and similar variables with a single group of more than 32768 atoms (`GROUPA` only, with `NLIST`) contained wrong pairs and could crash (32-bit overflow).
    - With `NLISTCELLS` and `NOPBC`, the cells were built on the periodic box and close pairs on the two sides of the planes at half box were missed. `NLISTCELLS` now also keeps only the pairs within `NL_CUTOFF`, as `NLIST` does (the list contained all the pairs of neighboring cells, about 6 times more), and it is parallelized with MPI and OpenMP (with 20000 atoms and a list updated every 5 steps, 4.7 times faster in serial).
    - Neighbor lists built with several OpenMP threads have the pairs in the same order as in serial: before, the order depended on the timing of the threads, so that two runs with the same input could give slightly different results.
    - Link cells (used by `NLISTCELLS`, [CONTACT_MATRIX](CONTACT_MATRIX.md) and the other adjacency matrices) are built on every process without MPI communication, and their number is limited.
    - Shuffling (used by [METAINFERENCE](METAINFERENCE.md) with `MC_CHUNKSIZE` to choose the uncertainties that are moved) only produced cyclic permutations, so that the choice was not uniform (e.g. with two uncertainties, one step and chunks of one, the first uncertainty was never moved).
    - Text files (e.g. hills files, grids, colvar files) are read in chunks instead of one character at a time, and numbers are converted with `std::from_chars` (when available) instead of a string stream: [sum_hills](sum_hills.md) on 300000 hills went from 9.8 to 2.5 seconds.
    - `nan`, `inf` and `-inf`, as written by PLUMED in its output files, are read correctly; negative numbers are not accepted anymore where an unsigned integer is expected (e.g. `STRIDE=-1` was read as 4294967295).
    - Output files are written without two MPI collective operations per line, and with MPI they are opened only by the first process (the other processes open `/dev/null`): opening and truncating the same file from all the processes is slow on parallel file systems.
    - In single precision (e.g. the OpenACC implementation of [DISTANCE](DISTANCE.md)), periodic boundary conditions in triclinic boxes were applied with an error up to 4e-6 times the box size; they are now exact.
    - Values outside a grid on its lower side give an error on all architectures (on arm64, e.g. Apple Silicon, they gave the value of the first bin).

  - Fixes and speed-ups in the core of PLUMED:
    - Less overhead per action and per step: OpenMP threads are used to clear the derivatives and to sum the forces of an action only when there is enough work.
      Before, two OpenMP regions were opened for every action at every step, which was expensive when PLUMED runs with several threads
      (e.g. GROMACS passes its number of OpenMP threads to PLUMED). With `plumed benchmark`, 400 atoms, 200 [DISTANCE](DISTANCE.md) and 200 [RESTRAINT](RESTRAINT.md),
      a step went from 226 to 85 microseconds with one thread and from 513 to 85 microseconds with two threads.
    - Forces on virtual atoms ([CENTER](CENTER.md), [COM](COM.md), ...) are applied 3 times faster: they were computed twice.
    - Reading an input with many actions is much faster (the time grew quadratically with the number of actions): 8000 [DISTANCE](DISTANCE.md) lines are read in 0.4 seconds instead of 17.5.
    - Forces on the elements of a sparse matrix that is not square (e.g. [CONTACT_MATRIX](CONTACT_MATRIX.md) with GROUPA, GROUPB and a cutoff) passed through [FLATTEN](FLATTEN.md)
      were added to the wrong elements, and a linear function of a flattened sparse matrix (e.g. its [SUM](SUM.md)) stopped with an error.
    - `UPDATE_IF ARG=... END` without a matching opening [UPDATE_IF](UPDATE_IF.md) is now an input error (it led to undefined behavior).
    - With replica exchange through the GREX interface (e.g. Hamiltonian replica exchange with GROMACS), PLUMED stops with an error if the two replicas exchange states of different size, instead of reading a truncated state.
    - The labels of the detailed timers (`DEBUG DETAILED_TIMERS`) were shifted after the actions that are computed during the update step.
  - [COMBINE](COMBINE.md) has a new CIRCULAR flag to combine periodic arguments as angles: the output is the argument of $\sum_i c_i e^{i p_i \theta_i}$
    (with the default coefficients, the circular mean of the arguments), scaled to the domain given with PERIODIC ([#164](https://github.com/plumed/plumed2/issues/164)).
  - Bug fixes in the functions. Results change in the following cases:
    - Elements of a vector whose arguments are all zero (e.g. the output of [LESS_THAN](LESS_THAN.md) with a D_MAX, or of a [CONTACT_MATRIX](CONTACT_MATRIX.md) row sum) were set to zero
      without evaluating the function, which is wrong when the function is not zero there: e.g. [CUSTOM](CUSTOM.md) with `FUNC=x+1`, [COMBINE](COMBINE.md) with PARAMETERS,
      [LESS_THAN](LESS_THAN.md) and [BETWEEN](BETWEEN.md) around zero. For example, [COORDINATIONNUMBER](COORDINATIONNUMBER.md) with LESS_THAN did not count the atoms with no neighbors
      within D_MAX.
    - [CUSTOM](CUSTOM.md) set the function to zero when an argument that is zero (with zero derivative) appeared in a product anywhere in the expression,
      e.g. `FUNC=x*cos(y)+1` or `FUNC=exp(x)*y`. Only the arguments that multiply the whole expression are now used for this.
    - Forces were lost when [SORT](SORT.md), [MOMENTS](MOMENTS.md), [HIGHEST](HIGHEST.md) or [LOWEST](LOWEST.md) take a single vector or matrix in input and only components other than
      the first are biased (e.g. `sort.4`, `m.moment-3`), and they were applied to the wrong elements of a sparse matrix.
    - [MOMENTS](MOMENTS.md) of periodic variables were wrong (the circular mean was shifted by half a period); the derivative of the circular mean is now included.
    - [PRODUCT](PRODUCT.md), and thus [DETERMINANT](DETERMINANT.md), gave nan for negative values (it was computed as the exponential of a sum of logarithms) and did not accept periodic scalars.
    - [FUNCPATHMSD](FUNCPATHMSD.md) and [FUNCPATHGENERAL](FUNCPATHGENERAL.md) no longer underflow far from the path (FUNCPATHMSD gave nan); FUNCPATHMSD accepts [DISTANCE](DISTANCE.md) arguments again;
      NEIGH_SIZE requires a positive NEIGH_STRIDE.
    - The documentation of [BESSEL](BESSEL.md) now states that it computes the exponentially scaled function $e^{-|x|}I_0(x)$.

### Changes relevant for developers:

  - `ActionSet` keeps an index of its actions, so that `selectWithLabel`, `getShortcutActionWithLabel`, `selectLatest<GenericMolInfo*>` and `ActionAtomistic::getAtomValuesFromPlumedObject`
    do not scan all the actions anymore. The index is extended with the actions appended to the set since the last lookup (actions must only be appended, as `PlumedMain` does)
    and is rebuilt if the set is cleared. New methods `ActionSet::getAtomValues` and `ActionSet::getNumberOfActionsForInterface`.
  - The bound check in `Value::get` was never compiled (`#ifdef DNDEBUG`): it is now active in debug builds.
  - `LeptonCall` can be copied safely (copies pointed to the variables of the original expressions).
  - `FunctionOfVector` evaluates the function at zero arguments when it is constructed; elements whose arguments are all zero are skipped only if the result is zero (`function::functionIsZeroWhenArgumentsAreZero`).
  - `LinkCells` does not use its communicator anymore (the constructor argument is kept for compatibility). `IFile::getline` reads lines in chunks. `Communicator` frees the communicators obtained with `Split` and handles `Set_comm(MPI_COMM_SELF)`; its copy constructor does not read an uninitialized communicator.
  - Faster build and installation:
    - Each source file is now compiled only once (the second compilation, which was left over after the dependency files started to be generated by the compiler itself, has been removed), and dependency files are written directly in `deps/`.
    - The python interface (both the one in `python/` and the one built during `make install`) is not rebuilt anymore at every `make`/`make install`, but only when its sources or the configuration change.
    - `make install` does not build anymore the python interface in `python/`, since the installed one is built separately against the installed kernel.
    - The files generated by running plumed (`vim/syntax`, `vim/help`, `json/syntax.json`) are regenerated only when the plumed executable changes.
    - With `make -j`, the python interface is now built concurrently with the C++ code, and the libraries in `src/lib` and in `src/lib/install` are linked concurrently.
    - The python interface is compiled from the committed `python/plumed.c`, so building it does not require cython and does not modify tracked files anymore. `plumed.c` is regenerated from `plumed.pyx` and `cplumed.pxd` only when they change (or with `make -C python cythonize`), and must then be committed; its consistency is checked in the CI.
  - `Subprocess` launches the command in a new process group and sends the signals to the whole group, so that they also reach the processes started by the shell.
    `Subprocess::stop()` and `Subprocess::cont()` (enabled with `PLUMED_ENABLE_SIGNALS`) now actually stop and resume these processes.
    When a `Subprocess` is destroyed, the group receives `SIGTERM` (and `SIGCONT`, in case it was stopped) and, if the shell has not exited after one second, `SIGKILL`.
  - The `xdrfile` and `molfile` modules are now always compiled: since the trajectory parser was moved to `src/tools` it requires them, and configuring with `--enable-modules=none` (or removing one of them) failed at link time.
  - The core module does not call blas directly anymore: the only call (a `daxpy` used to sum the forces in `ActionWithValue`) has been replaced by a plain loop, which is as fast and avoids calling a threaded blas within an OpenMP region. The configure warnings printed when the internal blas/lapack are used have been reworded, since the internal versions are only slower than an optimized external library with large matrices.
  - `pseudoInvert` builds the pseudoinverse with a single product, without the intermediate dense matrices; the result is the same and it is up to 2 times faster for large matrices. `diagMatRange` computes only a range of the eigenvalues and eigenvectors of a symmetric matrix.
  - The inputlines now are parsed using a dictionary instead of an array. This speeds up the parsing of massive input lines.
  - Abstracted the AtomDistribution functionality from the benchmark. It can be used in tests or in other
  - It is not possible anymore to register lowercase keywords and the developer must always specify the keywords completely as uppercase while parsing in the action constructor. There are no differences for the user, apart the entry in the manual for the DEBUG action: the user can still specify lowercase and mixed case keywords in the input file.
  - Some improvements in the management of the plugins:
    - Now the plugins have a common directory structure
    - The plugins now are checked with codechek.
    - The plugins now will be formatted with the astyle target in the main directory
    - The plugins will **NOT** be cleaned with the clean command from the main directory
  - Removed the optional `--enable-boost_graph` configure option and the `__PLUMED_HAS_BOOST_GRAPH` macro. The Boost branch of [DFSCLUSTERING](DFSCLUSTERING.md) was disabled by default, no longer compiled against the current code, and not tested in the CI; the built-in depth first search is now always used.
  - Added a new python workflow in the CI for checking the python interface and the `pycv` plugin with multiple python versions
  - Part of the python scripts are now checked for errors and for formattation in the CI.
    - The formattation and the checking of the code are made with the ruff python package
    - The astyle target in the main Makefile will attempt to format the python scripts if finds ruff
  - The CI also runs every night on the master branch, and can be started by hand from the Actions tab.
  - A regtest can be marked as long with `plumed_long=yes` in its config: it then runs only when `PLUMED_LONG_TESTS=yes`, as in the nightly CI run, and not on pull requests.
