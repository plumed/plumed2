## Version 2.11 (under development)

This page contains changes that will end up in 2.11

### Changes relevant for users:

  - Updated the embedded Lepton and AsmJit libraries from OpenMM 8.6.1, preserving PLUMED-specific expression functions and semantics. Just-in-time compilation of [CUSTOM](CUSTOM.md) expressions and custom switching functions now supports AArch64, including Apple Silicon, and is enabled by default on supported architectures. It can be disabled with `./configure --disable-asmjit` or at runtime with `PLUMED_USE_ASMJIT=no`.

  - When using [MOLINFO](MOLINFO.md) with the `WHOLE` flag, PBCs in the following actions will be reconstructed using a minimum spanning tree based on the coordinates stored in the MOLFILE reference pdb.
  - When using the benchmark now it is possible to scale the atom distances in the synthetic atom distribution (the base atomic distance is 1)
  - [SAXS](SAXS.md) now accepts the `MARTINI_FF` keyword to select the Martini form-factor generation: `MARTINI_FF=2` (default) keeps the existing Martini 2.2 protein and nucleic-acid form factors, while `MARTINI_FF=3` selects Martini 3 protein form factors.
  - [SAXS](SAXS.md) includes bug fixes related to the `ONEBEAD` approach and nucleic acid in some corner case, as well as general improvements in performances and SANS calculation. 
  - [SAXS](SAXS.md) includes new ions parameters that can be used both in `ATOMISTIC` and `ONEBEAD` modes.
  - [METAINFERENCE](METAINFERENCE.md) includes stability fixes when restarting while parameter optimisation is running.
  - Added environment variable `PLUMED_LOG_FILE` to control the log file pathname when runnning with GROMACS (the log file was hardcoded as `PLUMED.OUT`)
  - Changed CUTOFF keyword in [DISTANCE_MATRIX](DISTANCE_MATRIX) to LINKCELL_CUTOFF to make the purpose of this keyword clearer.
  - The kernels of [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) are now force-shifted at KERNEL_CUTOFF, so that both their value and their derivative go to zero at the cutoff.
    Previously they were energy-shifted: their value went to zero at the cutoff, but their derivative jumped to zero there (see [#1463](https://github.com/plumed/plumed2/pull/1463)).
    Bias values and kernel heights change only in the far tails of the kernels, and forces change slightly, mostly early in a simulation.
    The script `FES_from_State.py` of the OPES tutorial uses the new kernels.
  - [OPES_METAD](OPES_METAD.md) and [OPES_METAD_EXPLORE](OPES_METAD_EXPLORE.md) now use their neighbor list by default, since it is exact and never slower; it can be switched off with NLIST_OFF.
    The NLIST flag is still accepted, and only adds the `nlker` and `nlsteps` components as in previous versions.
    The NLIST_PACE_RESET flag is removed: with WALKERS_MPI, the neighbor list is now always reset after each deposition.

### Changes relevant for developers:

  - The inputlines now are parsed using a dictionary instead of an array. This speeds up the parsing of massive input lines.
  - Abstracted the AtomDistribution functionality from the benchmark. It can be used in tests or in other
  - It is not possible anymore to register lowercase keywords and the developer must always specify the keywords completely as uppercase while parsing in the action constructor. There are no differences for the user, apart the entry in the manual for the DEBUG action: the user can still specify lowercase and mixed case keywords in the input file.
  - Some improvements in the management of the plugins:
    - Now the plugins have a common directory structure
    - The plugins now are checked with codechek.
    - The plugins now will be formatted with the astyle target in the main directory
    - The plugins will **NOT** be be cleaned with the clean command from the main directory
  - Removed the optional `--enable-boost_graph` configure option and the `__PLUMED_HAS_BOOST_GRAPH` macro. The Boost branch of [DFSCLUSTERING](DFSCLUSTERING.md) was disabled by default, no longer compiled against the current code, and not tested in the CI; the built-in depth first search is now always used.
  - Added a new python workflow in the CI for checking the python interface and the `pycv` plugin with multiple python versions
  - Part of the python scripts are now checked for errors and for formattation in the CI.
    - The formattation and the checking of the code are made with the ruff python package
    - The astyle target in the main Makefile will attempt to format the python scripts if finds ruff
  - The CI also runs every night on the master branch, and can be started by hand from the Actions tab.
  - A regtest can be marked as long with `plumed_long=yes` in its config: it then runs only when `PLUMED_LONG_TESTS=yes`, as in the nightly CI run, and not on pull requests.
